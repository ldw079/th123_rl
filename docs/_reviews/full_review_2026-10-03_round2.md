## 3. 本轮新发现（第九轮未覆盖）

### P1 — 重建后的 BC 库仍带两处分布偏差（bc_build.py）

1. **suika 对手 one-hot 写错槽位**: bc_build.py:213 `core[227 + min(opp_cid, 20)] = 1.0`，`opp_cid` 取**原始角色 ID**（suika=9 → **core[236]**）；而在线路径 train_tm `_wire_opp_ids` 注入的是**池序**（suika=2 → core[229]）。core[236] 落在段 11 的技能可用性块 [234..237] 内——**正是自家 R19 契约（修订2.7"只允许[o..o+2]"）明文禁止的写入**。后果: suika 对手的 BC 行 one-hot 位置与在线分布系统性错位，且覆盖了一个本应为零的维。reimu/marisa（ID 0/1 与池序巧合一致）不受影响。
2. **技能特征 8 维恒零**: bc_build.py:136 `fb = FeatureBuilder(n_macros)` 后**从未设置 `fb._char_name`** → feat_builder.build() 段 11 的技能等级（230-233）与手牌技能可用性（234-237）全部跳过填充；在线路径这两块恒为实值。全部 BC 行（三角色）与在线分布在这 8 维上系统性失配。
   - 两项叠加即: BC 锚/`bc_extra` 专家行教的是"没有技能信息、suika 标错位"的分布。**BC 库需要再次重建**（改两行）——本轮发现时距上次重建仅数小时，成本尚低。

### P2 — 可达

3. **KeyboardInterrupt 保存竞态**: train_tm.py:1505-1508 中断处理直接 `tr.ppo.save(...)`，**未 join `tr._upd_thread`**。后台更新线程可能正 (a) 经 Adam 改权重 → 主线程序列化出撕裂混合权重；或 (b) 同时在写**同一路径** `.tmp` 文件 → 交叉损坏的 npz + 双 os.replace。更新耗时 19-84s 与下一局（90-240s）重叠，随机中断撞上的概率估计 30-60%。这条路径的全部意义就是"干净存档"。修复: join 后再 save（并注意 join 后可不重复 save——worker 完成时已 save 过）。
4. **`_rotate_opp` 环境重建丢 lane 参数**: train_tm.py:653-655/:665-667 `self._make_env(self.env.base_port ...)` 无 `lane=`，而异常路径（:699-700/:713-714）有。异常重建后 `base_port` 是 train_rebuild 段的中段口，`_make_env` 无 lane 时默认锚定 `(port, port+9)`——10 宽行走会越入相邻 slot 的 12 宽车道（如 slot0 重建于 20861 → 车道 20861-20870 与 slot1 的 20862-20873 重叠）。僵尸口探测使碰撞成为响亮 RuntimeError 而非串流，代价是丢局+重建churn 喂 `_consec_fail`。`_next_port()`（:581-586）为不可达死代码（TMEnv 恒定义 base_port）。
5. **TypeError 分支绕过连续失败守卫**: train_tm.py:687-700 重建环境但**不递增 `_consec_fail`**（仅 :679/:724 递增）。持续性 TypeError 会以零学习烧完全部局数并 exit 0 → 监督器记"正常完成"不重启——正是 R19 修过的监督盲区在该分支的回归。
6. **崩溃局被标记为 terminal**: train_tm.py:1189 `truncated` 仅含超时；协议错/断连/90s 无帧结束的局走 `EP_TERMS=[True]` → GAE 尾部按零价值自举——异常结束局的尾部动作获得系统性负偏优势。鉴于崩溃史（数十局/晚），近期训练数据有非平凡比例被此偏置污染。

### P3 — 低频/潜伏/卫生

7. **episode 边界 sc 状态泄漏**: `_run_episode` 开场重置（:762-801）缺 `self._sc_reset()`（side_driver.reset_match 有）。上局以 sc: 步进行中结束时，陈旧状态机带入新局: 新 sc: 步不再解析目标（:970 仅 None 时设置），可在新局乱按 SW/SC、极端情况误判"已消费"烧掉一张卡。last_macro/last_macro2 同样未重置（仅污染首决策的 one-hot 历史，属外观级）。
8. **死仪表**: `_guard_decay_tracker`（:738-757）零调用者；每局打印的 `[奖励成分] ... 防御+0.0 墙-0.0 灵力+0.0` 恒零（对应通道 R35 已删）。按这行日志调参=读死表。建议连同 rew_mix 的 guard/wall/spirit 键一起清理。
9. **NaN 落盘守卫漏 bias**: ppo.py:400-402 只检查 W 系权重矩阵，**不含任何 b 系偏置向量**（b1/b2/bs1/bs2/bo1/bo2/bq1/bq2/b1v/b2v/b3v/bc1-3）——NaN 偏置可穿过"最后防线"毒化下次加载。
10. **`_load_bc_bank` 只校验 S 宽不校验 X 宽**（train_tm.py:545）: 旧 X 布局（≠14400）的 BC 文件会"健康"载入，然后在每次更新里 `_trunk` reshape 崩溃、被 worker except 吞掉 → 零学习且无可见错误。当前磁盘文件正确（X (16622,14400) 等），属潜伏。
