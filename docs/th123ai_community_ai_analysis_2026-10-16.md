## 1. 生态图景

- **本体**: th123_ai（作者 sweetie，2008-2010，VS2008/2013，已停滞）——
  外部 AI 工具：**ReadProcessMemory 只读 + keybd_event 键盘模拟 + Lua
  脚本引擎**。无代码注入；地址经 ini 配置。许可超宽松（公共领域级，
  可自由借鉴/移植）。
- **AI 本体 = Lua 脚本**：`main()` + 每帧 `yield()`（16ms/帧）决策循环。
  社区作者手写（しなうす 的灵梦 AI = **3138 行规则状态机**）。
- **AIManager**（本地有源码 1130 行）: 社区分发器（下载/上传/管理，
  GUI+HTTP+zip）。
- **cleista practice 页**: 这些 2011 年脚本的**现代移植与在线评测**——
  浏览器跑游戏 + 移植的 Lua AI，带胜率/等级分/点赞/对战次数，还有
  AI 编辑器（可 fork 改脚本）。等于社区给规则 AI 建了持续标尺。
- 版本注: 本地 document.txt 的动作/状态语义与我们的 SokuLib 表同源
  体系（action ID 口径兼容）。

## 2. 架构对照（逐项）

| 维度 | th123_ai (2011) | 本项目 | 判注 |
|---|---|---|---|
| 状态读取 | RPM 外部只读+ini 地址表 | mod TCP 状态包（训练）/RPM（B 标尺） | 同构；训练侧我们精确得多（锁步逐帧对齐 vs 他们明确接受同步不完整：偶发丢键/漏看弹幕=规格） |
| 行动输出 | keybd_event（与人同通道） | mod 输入包/内存写 | 他们天然公平但会丢键；我们训练零丢失 |
| 决策节拍 | 每帧 yield | 宏队列空+帧级事件 | 同为帧驱动；我们多事件通道与分支门 |
| **公平垫片** | **set_key_delay / set_data_delay（内置！）** | W1 垫片（设计中） | **2011 年先例，参数经验可抄** |
| 信息遮蔽 | weather_delay（极光解禁计时）/晴岚时 my_card=-1 | R11（mod 层遮蔽） | 同概念，我们更彻底 |
| 动作抽象 | `command("AA(10)A(5)236B(50)")` 字符串指令 | 宏系统+confirm/分支门 | 同构，我们更强 |
| **对位支持** | `require("対%c2ガード.ai")` 按对手角色换脚本 | 对位 one-hot+先验表(BH-4.3) | 他们是显式 per-matchup 脚本——**对位定制是社区标配** |
| 对战对象数据 | get_obj_data（id/x/y/hp/速度/**攻击范围数/食らい范围数/状态/攻击标志**）+ get_opt_xy（**人偶/半灵/小町灵魂坐标直读**） | objs 17 字节运动学点（CE-2 语义缺失） | **他们能拿到对象语义——CE-0 首字节=朝向的结论需要复查其余 4×u16** |

## 3. 观察 API = JZ/CE 系列的存在性证明（最大收获）

th123ai 的环境变量表逐条对照我们的计划项：

| 他们直读的变量 | 我们的状态 | 对应计划 |
|---|---|---|
| **my_rei_stop/enemy_rei_stop（灵力回复停止帧）** | 无（要用出招历史推算） | JZ-1 A2——**内存里有现成字段，SWRSAddr-110.ini 有偏移** |
| **my_limit/enemy_limit（LIMIT 出圈值）** | 封包有 comboLimit 字段，特征零消费 | JZ-1 A3——2011 年就被 AI 作者认为必要 |
| my_rmax（最大灵力=破珠） | 封包有 maxSpirit，零消费 | JZ-1 A5 |
| my_air/enemy_air（空中 dash 次数） | 封包有 airDashCount，零消费 | JZ-1 A1 |
| **weather2（天气预报）+ weather_time（气质计数×10）** | 只有当前天气+timer | LE-2 预报特征（存在性证明） |
| my_hitstop/enemy_hitstop 双侧 | 仅己方布尔 | JZ A7 |
| get_skill_lv（技能等级 0-4） | 封包 15 字节零消费 | JZ-1 A4 |
| battle_time（对局帧） | 无 | 佐证：引擎有对局时钟（攻略"无时限"指规则层） |

**结论：我们的封包早就带着这些字段（CS_FIELDS），缺的只是消费**——
th123ai 用 2011 年的实践为 JZ-1 的全部字段做了必要性背书；而
SWRSAddr-110.ini 是现成的内存偏移地图（B 标尺/RPM 侧补字段按图索骥）。

## 4. 策略层（社区 AI 的真实水平与本质）

- しなうす 灵梦 AI（3138 行）: my_act/enemy_act/天气/距离的规则状态机；
  起身 75% 移动起身+方向选择（版边远离/中央朝对手防设置技）；破防连/
  特殊连的**手写连段状态标志**；卡管理（手牌 ID 判断+AB/BC 交替）；
  彩蛋"超反应模式"（特定舞台/BGM 触发）。
- **社区 AI 的"强"本质 = 超反应**：每帧读内存+零反应延迟+确定性规则。
  cleista 的胜率/等级分是在其公平垫片（key/data delay）下测的。
- 天花板: 固定策略、零适应、零学习——被针对一次就永久克制。

## 5. 对本项目的可执行借鉴（按价值排）

1. **league/评估新对手族（最有价值）**：th123ai 规则 AI 是现成的
   20 角色强基线——**接入评估矩阵作第四口径**（COM/league 镜像/人之外
   加"2011 社区 AI 水平线"）：对局形态 = th123_ai 跑 P1（自带 RPM 读+
   键盘输出）× 我方模型跑 P2（mod 输入）——与 BO5 人测同基建，零人类
   时间成本，可高频测量。给"相对 2"一个外部锚点；league 静态位也可
   逐步换入（比镜像多样）。限制: keybd_event 需窗口焦点 → 评估会话
   串行跑，不适合并行 fleet。
2. **SWRSAddr-110.ini 入档为数据参考**（B 标尺偏移地图+RPM 补字段）。
3. **CE-2 复查探针**: get_obj_data 证明对象有攻击/受击标志与范围数
   ——CE-0"首字节=朝向"结论不排除 4×u16 中含类型语义，安排复查。
4. **W1 垫片参数参考**: 社区 delay 使用的默认量级。
5. JZ-1 维持优先级（2011 先例背书）。

## 6. 一句话总评

th123ai 与我们**同构而不同代**：同样的"RPM 观察+帧决策+指令抽象"，
他们 2011 年用 3138 行手写规则做到了社区标尺级；我们用学习替代手写，
但他们的**观察 API 设计（尤其公平垫片/信息遮蔽/对象语义/对位脚本）**
是一份被十年验证过的需求清单——我们计划里缺的他们早就有，我们封包里
有的他们证明有用。
