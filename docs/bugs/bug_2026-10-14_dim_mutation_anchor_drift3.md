# Bug: 维度变异锚死串第三次复发 — 应改为活常量派生(已修+验收+防复发)

- **发现**: 2026-10-14 从严审计(S-2 维度扩波), 审查者亲验。
- **症状**: tools/gate_selftest.py:140 变异锚钉死串 `CORE_DIMS = 330`,
  而 feat_builder.py:77 现为 343(S-2 扩维) — 变异永不生效, 维度漂移
  防线再次假绿。
- **复发史**(同类第三次): P1-1(R80 修, 316→330 未迁)→ drift2(R80 修
  +根治断言入常驻门禁)→ 本次(330→343 未迁)。**根治断言只防了沙箱
  FILES 清单漂移, 没防变异锚死串漂移** — 每次维度变更都在重演。
- **根因**: 变异条目是静态字符串表, 无法跟随活常量。
- **修复与验证**: **已修(2026-10-14 晚, R109)**, 按本档根治建议执行:
  ①`_rederive_dim_anchors()` — gate_selftest 启动时导入 feat_builder
  取活值, 凡锚串匹配 `^CORE_DIMS = \d+$` 一律重写为
  `CORE_DIMS = %活值 / %活值-1`(现役锚已验=343→342; 未来358/362
  迁移零维护); ②横扫全部静态维度锚: learner_hub条目的目标串本身是
  活派生表达式(`5 * n_out + FeatureBuilder.CORE_DIMS`)天生防漂移,
  其余数字字面量为稳定动作枚举/距离常量, 不属维度族, 免改。
  **验收(本档验证项)**: 派生锚命中现源→应用343→342→导入副本
  CORE_DIMS==342→C2契约断言失败→门禁红 — "手改后仍红"实证通过
  (原bug行为=永不红)。
- **防复发**: 已落地, 比本档建议更宽的**通用维度锚活性自检**
  (`check_anchor_liveness`): 凡锚串含 `NAME = 数字` 且目标文件存在
  同名赋值(含类内缩进属性)但值不同 → 导入期即响亮退出(exit 2),
  与FILES完备性根治断言并列。四向验证: 现役锚全过 / 植回死锚330
  被抓 / 通用族仿冒死锚(OPP_GRU_H=20 vs 实际24)被抓 / 与活值一致
  的锚不误报。教训补充: 首版正则漏缩进(CORE_DIMS是类属性)。
- **状态**: ✅已修+验收+防复发(2026-10-14晚)。关联: 同轮审计P2对账
  发现21个测试未注册C15行为白名单(gru等价测试=漂移闸从未在门禁
  里跑过), 已70/70全量入账 — 见METHODOLOGY 3.18(R109)。
