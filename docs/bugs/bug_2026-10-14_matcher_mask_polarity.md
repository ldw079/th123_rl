# Bug: v3 匹配器方向轴掩码极性反转(P0, 在途未提交代码)

- **发现**: 2026-10-14 凌晨, rep 动作→宏映射专项从严审计(动态往返测试)。
- **症状**(全部动态实证, threshold=0.88): 任意方向流标签系统性错乱 —
  待机(全中性)→"跳跃"1.00; 左移→"后跳"1.00; 右移→"后跳"1.00;
  2B(下+B)→"5B"1.00; 6B→"5B"; j2B→"5B"; 6C→"5C"。**前进/后退在输入域
  完全不可区分**(约束逐帧解剖: 两宏 mask 同为 H-wild+V-neutral);
  "空防"(第一步 up+left)双轴全 wild+按钮全 False = **任意无按键窗口的
  万能吞噬器**。
- **根因**: bc_match.py constraints() 的 has_dir 分支掩码极性写反:
  `m = [0 if (right/left in ks) else 1, 0 if (up/down in ks) else 1, ...]`
  配合 `sat = (win==req) | ~req_mask` 的语义(mask=0 才是 wild) —
  实际效果是**指定方向轴设为 wild、交叉轴设为约束**, 与 docstring
  "指定轴match, 交叉轴wild"恰好相反。
- **引入**: 在途未提交的 StreamMatcher v3(A1-3③, 工作区 2026-10-14)。
  v2(现行已提交路径)无此问题(方向语义正确, 只是漏标弹幕)。
- **影响面**: 若按现状合入并重建 BC 库 — 全部方向可分宏(前进/后退/
  6系/2系/4系/8系/空中方向技/方向系移动)标签系统性污染, BC 专家信号
  方向盲。**幸在合入前被截获**。
- **修复与验证**: **已修(2026-10-14, 在后续波次落地 — 从零#4对账确认)**:
  has_dir 分支掩码值按修法交换(指定轴=约束, 交叉轴=wild), 与 docstring
  语义一致。验证: tests/test_bc_match_v3.py 11项(掩码位/方向区分/
  变长截断/漂移/镜像)全绿并已入C15行为门禁; 同日 bc_match v3.4 三库
  重建+换装(重建行数与方向宏分布健康)为实战确认。
- **防复发**: 匹配器行为测试必须含"方向互斥对"(前进 vs 后退/2B vs
  5B/8A vs 2A)断言 — 掩码类缺陷只有对抗性用例能拦。
- **状态**: ✅已修+验证(2026-10-14; 档头"在途未提交"为历史时点描述,
  从零#4审计对账时已修复, 本档2026-10-14晚回填)。
