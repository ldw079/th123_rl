# Bug: B3 距离列号误用己方站位(已修, 溯及归档)

- **发现**: 2026-10-12, 工作会话施工中自查发现(用户通报并要求核实,
  审计会话独立实证确认)。
- **症状**: B3 工具把 `own_x/620`(己方站位)解码为 `|dx|/600`(距离) —
  "远程决策/远程弹幕份额"实际测的是"站在舞台右侧", 阈值语义变为
  `own_x ≥ 330/600×620 ≈ 341px`(舞台右侧约 45% 区域)。
- **根因**: `ADX_COL_IN_CORE = 5`; feat_builder.build 的 vals16 实际
  布局: col4 = `clip(adx/600)`(feat_builder.py:373),
  col5 = `left["position.x"]/620`(feat_builder.py:374)。分型:
  **共享常量错** — 工具与配对测试各自硬编码同一个错列号, 断言与实现
  同错, 天然自洽。
- **引入**: f2fe368(2.65, B3 工具初版)。
- **影响面**(点名作废):
  - `tools/b3_baseline_20261011.json` — **首份 B3 基线整体作废**
    (marisa"远程决策 100%/弹幕份额 0.3%"测的是站位右偏, 非距离);
  - 10-11 会话与 `docs/audit/audit_2026-10-11_code_health.md` 结论 6
    中引用的 B3 数字(远程份额 marisa 0.3%/reimu 2~7%/suika 0~11%)
    作废(归档不改写原文, 本档即更正注);
  - **不受影响**: F6 全顶时段、E1 分支观察等独立证据链 — 被动性
    问题本身不动摇(走不同测量路径)。
- **修复与验证**(R67c, commit 51681c2): `ADX_COL_IN_CORE = 4`;
  配对测试新增 `calibrate_adx_col()` 标定 — 已知几何(left.x=100 等)
  走**真实 feat_builder** 构建特征反查命中列, 带符号输入消歧
  dx/adx(单位幅下二者不可分)。独立会话实测: 10 PASS / 0 FAIL,
  标定唯一命中 col4。v3.1/主规划/方案档同步更正。
- **防复发**: 标定测试独立于工具实现(不共享常量) — 这是"断言与实现
  同错 = 变异盲区"的标准解法; 教训已入 bug_protocol 规则 5。
- **状态**: 已修(51681c2); 新基线待采集(被
  bug_2026-10-12_b3_empty_window_keyerror 阻塞)。
