# Bug: fleet 重启耗尽=静默永久减员(✅已修+验证)

- **发现**: 2026-10-14 从零#4 分片C(日志实证)。
- **症状**: fleet_supervisor.py MAX_RESTARTS 耗尽仅 `del actors[key]`,
  无告警、无暂停账本(与 R75 CPU 暂停不对称)。日志实证: 10-14 16:12 起
  marisa actor 因 BC 宽度 assert 连环崩(code=1), 16:13:53 耗尽放弃 →
  车队缺 marisa **1.6 小时无显眼告警**(17:54 人工重启)。
- **根因**: 重启预算语义只有"冷却+上限", 没有"耗尽=事故"的升级路径。
- **影响面**: 任何持续崩溃(如代际迁移期)都会变成静默容量损失;
  learner 饿死、A/B 断流。
- **修复与验证**: **已修(2026-10-14晚)**, 按本档修法+加宽:
  ①耗尽时监督日志 `!!ALERT!!` 行(含key与次数, 指明查actor日志);
  ②心跳异常标记文件 `fleet_heartbeat.alert`(主时间戳格式不变 —
  offline-gap 读数兼容, 独立文件防float解析破坏);
  ③主循环节流重播(每18循环≈3min)减员在案提醒 — 静默期上限3分钟;
  ④周期心跳携带alert(无参调用不再误清alert文件)。
  验证: 模拟耗尽路径全链 — ALERT行入日志/alert文件写入/时间戳读数
  兼容/恢复调用清除alert 四项通过。恢复路径=人工(如档建议)。
- **防复发**: fleet 状态仪表"编制 vs 应有编制"对账(待audit_all批次);
  与P0-3的点火BC宽度硬门禁构成双保险(根因链上游拦截)。
- **状态**: ✅已修+验证(2026-10-14晚)。
