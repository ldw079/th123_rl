## 1. W1 能力归因档案 — 延迟消融评估通道(最高优先)

**目标**: 同一模型快照在 k 帧观察延迟下评估, 产出"强度-延迟曲线"——
未来一切"超人"主张的前提(笔记 §四.7: 曲线斜率本身即结论)。

- **接入点**: 新增 `tools/attribution_probe.py`; 修改
  `tools/eval_matrix.py:51 run_matchup` 增加 `delay_frames=0` 参数——
  在**己方**驱动的状态读取处包一层 `DelayedView(k)` 状态延迟垫片(策略
  特征构建与事件检测消费 t-k 帧的状态视图; 计分/日志用真值不受影响);
  对手侧不延迟(测的是"我们让步多少")。延迟垫片实现于
  attribution_probe.py, eval_matrix 只传参(单一真值源)。
- **档位**(用户裁定 2026-10-13, 原文回显: "延迟80ms即可, 原文的200ms
  太夸张了"): k ∈ {0, 3, 5, 8} 帧(≈0/48/81/129ms@62fps), **主档 5 帧
  (≈81ms)**。文献 230-240ms 仅作外部参照留档, 不作本项目包络。
- **工作量**: 2-3 人日(垫片 1 + eval_matrix 接线 0.5 + 报告输出 0.5 +
  测试/变异 0.5)。
- **回滚**: eval_matrix 缺省 delay_frames=0 逐位等价(回归线); 垫片独立
  模块可整体摘除。
- **制度对齐**: 新模块+新调用方配对集成测试入 C15; 变异钉(把 k 帧垫片
  改成 k+1 → 曲线断言必须红); 门禁全绿后提交。
- **风险表**: ①状态延迟垫片与帧级事件(frame_events)交互改变掩码时序
  → 设计上事件检测消费同一延迟视图(一致延迟), 测试断言延迟下事件数
  单调不增; ②与在跑 fleet 抢 CPU → 用 probe 保留端口段+错峰(先例:
  expert_harvest 与 fleet 并存 tps 预算)。

## 2. W2 反事实危险显影卡(第二优先)

**目标**: 局面→强制替代宏→N 次续演→结果分布对比(笔记 §七"危险显影卡"
最小版; 宏动作天然规避 §7.6 单帧替换失真)。

- **阶段 0(可行性探针, 0.5 人日)**: 验证 `branch_demo.setup_scenario`
  能否从 episode/rep 重建观测到的关键局面(位置/血量/灵力/卡牌)。
  **若不能**(场景 API 只支持合成位置): 回退设计 = 回合起点重放至第 F 帧
  (oracle staged rep 慢放到 F 后切锁步), 复用 `run_one` 的
  TrainerClient 通道; 两案均不通则 **[用户裁定项 B]** 是否立项 mod 侧
  状态注入(走血统流程, 工作量另议)。
- **阶段 1(1.5-2 人日)**: 新增 `tools/danger_reveal.py`: 输入(局面, 实际
  宏, 替代宏, 对手规格, N≥20) → 续演分布(胜/负/伤害分布/危险兑现率)
  + 对比表(实际 vs 替代); 输出结构对齐"危险显影卡"字段(局面/实际/
  诱人替代/惩罚条件/概率/人类条件标注列暂空)。
- **阶段 2(1 人日)**: 与 habit_punish_demo 教学闭环对接(习惯→其替代
  路线的危险分布)。
- **回滚**: 纯新增工具, 无训练面改动; 阶段间独立。
- **制度对齐**: 集成测试(合成必败分支检出率)+变异钉; 归因隔离纪律
  (观测工具不触训练, 先例 B3)。
- **风险表**: ①强制偏离后原策略分布外崩溃被误读为"路线危险"(笔记
  §7.7)→ 报告区分"原策略接管/该路线专家接管"两种续演, 首版至少标注
  接管者; ②单一对手规格的稻草人风险(§7.4)→ 对手规格必须含 ≥2 风格
  (对手池快照+COM)才可出报告。
