# 方法论复盘（审计侧）：为何漏检/为何指标没靶（task-66 草案，2026-10-26）
> 基线 HEAD `5498a7f`；只读；R15（行为基座/独立真值）自审；不改代码/不部署。供 `methodology_retro` 引用/合并。
> 立场：审计不是"数门禁/对任务"，而是**独立验证用户观察是否被真实行为改善**。以下每条给：现象/证据/审计侧根因/制度建议/前置拦截动作。

## 0. 一句话结论
过去多轮"门禁全绿/任务完成"与"用户观察未改善/事故复发"并存，根因不在测试数量，而在**验收范式**：没有预注册的主行为指标、没有独立真值、没有固定评估基准、没有事故闭环；审计在实现后介入且被门禁数字牵着走。

## 1. 同源自证为何直到 R15 才被当作问题
- **现象/证据**：BC 合成锚由采集回放 `execute_macro`/`capture_row` 生成、再由同一 executor 复验（"严格 1.00"），QC 由同一 npz 聚合；此前 replay/QC 也常由训练同一逻辑产生；门禁 `gate_audit_20261025` 中 76 条纯 `src()` 断言无行为基座；Gen-1 记忆双零初始化等"门禁绿但未学习"先例。
- **审计侧根因**：①验收默认"测试存在/源码含锚点"=通过，未定义**独立真值**；②审计只读检查"有没有测"，未检查"测的是不是同一 bug 逻辑"；③R15 之前无成文红线，审计无据拒绝"自证式绿"；④审计在实现后取样，缺设计阶段合同。
- **制度建议**：R15 升为**验收前提**（本会话已写入 `docs/audit_protocol.md` §四）：任何行为断言必须给行为基座+独立真值（真实帧/手动输入/独立 replay/盲抽样）；**禁止同源 replay/QC 自证**；变异锚点必须使行为测试红；新增门禁先审后入。
- **前置拦截**：设计评审时即要求"独立真值方案"；材料评审先查生成/复验是否共用 executor；QC 报告必须附独立抽样命令/样本表。

## 2. 行为类变更缺预注册/样本门 → 不可归因
- **现象/证据**：C1/C2 熵窗、A′/UKEMI、B 批等窗口的 ent/KL/选择率常在小样本/不同窗口下比较；A′ 34min 数据先判后改 2–4h；窗口起止按小时标签而非 commit/restart（曾把 2a 误当"未 2a"）；多变更叠加（R209/R210/Gen-1/R214/R215/C1/C2）后无法单独归因。
- **审计侧根因**：①无实验预注册（主指标/窗口/样本门/停止规则）；②审计接受"事后叙事"而非事先合同；③未强制 commit/restart 切窗与样本充分性；④无"不可归因"的显式标注规范（虽报告写了，但制度未前置）。
- **制度建议**：**实验预注册单**（hypothesis/单变量/主指标/固定窗/最小样本/CI/停止/回滚/归因边界）由审计在窗**前**签；窗后只按预注册判；样本不足=不判；commit/restart 时刻为唯一窗边界；多变更窗必须写"不可单独归因"并留对照臂/回归。
- **前置拦截**：窗计划进任务板前先过审计 AC；窗后报告必须引用预注册单编号；未预注册的"改善"只作探索性，不进验收。

## 3. north-star 行为指标缺失 → 用门禁数/任务完成代替用户观察
- **现象/证据**：用户三观察（主动性/逃压/空间感知）长期存在；多轮报告以门禁 PASS/任务完成/曲线改善为主，直到行为诊断才量化 strict 攻击、非硬直移动、wall_air_share 等；策略仍 80%+ 远弹被动、逼近 17%、back/up 低、挂角时间上升。
- **审计侧根因**：①无**用户观察→可操作指标**的 north-star 表；②验收以"门禁数/任务完成"计，不以"用户能否感到改善"计；③审计报告缺少面向用户的主指标与失败样例；④指标口径演进（masked_choice/pref_mass 等）未注册。
- **制度建议**：建立 **north-star Behavior Metrics Registry**：每条用户观察→1–3 个主指标（定义/分母/窗口/样本门/CI/反例帧）；审计报告开篇给主指标与"是否改善"；门禁数/任务完成**不得**作为行为验收；每 24–48h 由审计出用户可读行为摘要；指标变更须注册并保留旧口径。
- **前置拦截**：任何"行为类变更"任务必须先在 registry 绑定主指标；无 north-star 绑定的任务不得宣称效果。

## 4. 评估基准缺失（frozen eval）→ 无法判断真改善
- **现象/证据**：模型制品 plain/fleet/_v/_pre_* 多代并存、plain meta 与 fleet 不一致；池旧快照拒载→回退生产；BC 822/831 混代际；评估常随训练态/池/对手变化，无固定 frozen eval；同一策略不同时间数字不可比。
- **审计侧根因**：①无固定夹具（模型/对手池/种子/帧）与基线快照；②审计接受"当前策略 vs 旧文档数字"；③制品/BC registry 缺失（C1 债）；④评估与训练共用动态环境。
- **制度建议**：**Frozen Eval**：固定模型快照+固定对手池+固定种子/帧 fixture；每次行为变更跑同一 frozen eval（含 replay/行为表）；基线快照入 registry；跨窗比较只用 frozen eval；训练侧指标仅作辅助。
- **前置拦截**：窗验收必须给 frozen eval 基线/前后对比；无基线=不判"改善"；C1 制品注册表为前置依赖。

## 5. 复盘制度（postmortem/决策日志）→ 闭环
- **现象/证据**：19:59 全灭/唤醒崩溃/窗#9 actor 崩-loop (`_buf_cnt`)/BC 锚标签泄漏等事故有临时处置，但无统一 postmortem 与"决策-行动-验证"闭环；类似问题反复（记忆双零、mask 口径、plain 同步、同源自证）。
- **审计侧根因**：①审计只报问题，不跟踪修复验证到关闭；②无 decision log/owner/deadline；③事故根因未沉淀成验收项；④"已修"以提交信息为准。
- **制度建议**：**Postmortem + Decision Log**：每 P0/P1 事故/重大裁定一条（现象/根因/动作/owner/deadline/验证证据/关闭状态）；审计每轮检查未闭项；同类根因→新增 AC/回归用例；关闭需行为证据，不以提交信息结案；月度复盘看板。
- **前置拦截**：P0/P1 未闭环不得进入下一阶段大迁移（W4/Gen-2 等）；决策日志作为阶段门输入。

## 6. 审计流程改造（落地清单）
1) **设计阶段**：AC 合同（C1/C2/C3/W4 模式）先审；独立真值/north-star/frozen eval 方案必须随设计提交。
2) **实现阶段**：只接受行为/契约证据；R15 红线；纯串断言不计 PASS；变异须行为红。
3) **窗阶段**：预注册单+commit/restart 切窗+样本门；审计窗后复测，样本不足=不判。
4) **部署阶段**：备份/原子/回滚/三面 hash；frozen eval 前后对比；失败单次回滚。
5) **复盘阶段**：postmortem/decision log 闭环；同类根因→新 AC；未闭环不迁移。
6) **报告规范**：主指标/样本/CI/失败帧/归因边界/未证实标注；禁止"门禁全绿=行为改善"。
