## 1. 严审新发现

### S1（高·重启即生效）deck 激活约九成死接线

- `_restart_same_process`（tm_env.py:524-528）的开局包仍用 `bytes(self.deck)` **双侧系统卡**——而同进程续局是**每局结束的主路径**（GameEnded→续局; 仅协议错误才进程重启）。
- 实际效果: 每个 env 进程只有第一局（`_start_first`:342-343 用 deck_left/right）是采样卡组，其后所有续局退回系统卡 1-20。R47"卡组系统激活"在实践中 **~90% 失效**——技能卡/SC 卡仍然几乎永不入手，天花板 2 的处置名不副实。
- 讽刺证据: 门禁"deck采样器接入训练(R47天花板2)"断言**绿**——它只查子串存在。
- 修法: 续局包改用 `self.deck_left if ... else self.deck`（与 :342-343 同源两行）。

### S2（高·当前未接线=危险死代码）ppo_gpu.py 不可用

逐行严审发现**六重缺陷**:

1. **维度陈旧**: `CONV1/2/3_F = 16/32/32, TRUNK_FLAT=1280`——按**旧架构**写的; 现行 numpy 版是 32/64/64、2560。与全部现存模型不兼容。
2. **对手切片偏移错误**: sample/update 传 `opp_off = 2*n_out`; 正确位置是 `2*N_OUT + 152`（OPP_CORE_OFF）。**对手子网读的是 core 的前 75 维**（核心标量/动作类/朝向/位置带）——完全错误的特征。
3. **save 格式不兼容**: 存的是 torch 平键 state_dict（`fc1_weight`…）+ `v_path` 只写 dummy——numpy 加载器（W1/W2/W_side/W1v…）读不了。docstring"与CPU版格式兼容"为假。
4. **load 按形状随机匹配**: `_remap_keys` 用"形状相同即配对"重映射——同形张量众多（各 bias 全是不同长度但 (128,) 形状成堆、(n_out,) 层多个），映射本质随机; `strict=False` 掩盖缺失键。**加载即静默乱权重**。
5. **语义缺件**: `bc_extra` 参数接受但被 `**kw` 吞掉（BC 损失整体缺失）; Q 预测头前向算了但**从未监督**（aux 损失缺失）; 无回放; `self._rstd` 恒 1.0 不更新（归一化失效）; policy/value 共用 lr 3e-4（CPU 版 value 是 3e-3，值学习慢 10 倍）; 无 KL 自适应; **meta 字段顺序与 CPU 版不一致**（GPU 存 [temp,bcw,beta,…]，CPU 读 [temp,beta,bcw,…]——互换位，交叉加载即错）。
6. 文档称 minibatch=2048，实际 B=64。

当前 train_tm 仍 `import ppo`——未接线。但作为"天花板 1 处置"提交的模块，其存在本身就是风险（未来接线者会以为它可用）。
