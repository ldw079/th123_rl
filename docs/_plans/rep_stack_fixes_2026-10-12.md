## 1. 缺口与修复（按影响排序）

### 缺口 1 · AandB→SC 映射仍是 TO_VERIFY 假设【高·数据保真】
- **现状**: input_codec.py:204 `AandB→SC（常见解释, TO_VERIFY）`——R61g 的 SC 词汇整条链（SC 标签脱离 0%、三角色库重建）建立在此假设上;
- **风险**: 若实际映射不同, 全部 SC 标签系统性错位（当前占比 0.72-2.02%, 影响面小但随卡牌维度深化而放大）;
- **修复（验证式, 非改码优先）**: 跑批相关分析——rep 输入流的 **AandB 置位帧** × oracle 状态流的**手牌差分事件**（bc_build 的卡解析已用后者）做时序相关（容差 ±3 帧）; 判据: 吻合率 ≥90% → 假设升格实证, 更新 docstring 去 TO_VERIFY; 30-70% → 存在第二来源（如快捷键）, `battle_to_trainer` 加备注位; <30% → 映射错误, R61g 链路重审;
- **工作量**: 半天（oracle shards 在库, 跑批脚本 + 报告）;
- **验收**: 相关报告入档; input_codec 的 TO_VERIFY 标注按结论更新; 若升格实证, 配一条行为断言（合成 AandB 帧 → SC 位=1）+ 变异。

### 缺口 2 · 文件名比分语义未证实【中·专家分级解锁】
- **现状**: rep_meta.py 抽取 `(0:2_负)` 类原文但语义矛盾（0:2负 与 1:2胜 无法用"我:对方"一致解释）, 不当标签使用;
- **风险**: 阻塞两个下游能力——按胜负过滤低质量专家局、专家分级（强弱分层 BC）;
- **修复（交叉验证式）**: oracle 通道回放时 mod 发 GameEnded(winner, ls, rs) 为**地面真值**——跑批: 逐局取 GameEnded 真值 × 文件名比分, 统计四种语义假设（我:他 / 他:我 / 左:右 / 右:左）各自的一致率, 取显著胜出者定语义; 机制在位（v1 manifest 的 match 字段曾想做但全 null——修的是跑通不是新写）;
- **工作量**: 半天;
- **验收**: 语义结论入档（一致率数字支撑）; `rep_meta` 的 score 字段按结论标注"已验证/维持原文"; 一致率 <80% 时维持"原文-only"现状并记录。

### 缺口 3 · rep_file.frames() 内部陷阱【中·API 卫生】
- **现状**: `frames()`（:96-103）仍按**旧的错误顺序**产出并标注 left_raw/right_raw——而 `pair_input_frame`/`inputs_by_side` 是修正后的正解（[右,左] 实测裁定）。同一模块内并存一个带错误标签的旧 API, 正是当年 rep_drive 对调事故的根因形态（从零审计隔离区里 rep_distill 之死同源）;
- **风险**: 任何新消费者 import RepFile 用 frames() 即静默左右对调;
- **修复**: 二选一——(a) frames() 改为按验证序产出并加 docstring 指向裁定; (b) 直接删除, 迁移全部调用方到 inputs_by_side（grep 确认现役调用方为零, 推荐 b）;
- **工作量**: 十分钟;
- **验收**: 全库 grep frames( 无残留误用; 配一条防回归断言（inputs_by_side 首列=左, 与 inputlog 判定一致——已有测试钉住则确认覆盖）。

### 缺口 4 · flags 区未解析【低·不急】
- **现状**: @60-62/@109-116 原样保留（含疑似左右边标志 @61/62 互补位）;
- **修复**: 择机 hitlab 式探针（改 flags 位观察游戏行为变化）; 无消费方前不动;
- **验收**: 无（登记待办即可）。
