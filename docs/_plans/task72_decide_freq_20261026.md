# task-72 决策频率/可中断宏 设计 v0（2026-10-26）

> 目标：62fps 推理基准 + 混合决策（低频宏 + 每帧残差）+ 可中断宏 chunk + 蒸馏 fast policy 备选；
> 用 task-70 时序可复现率验证；先设计+离线基准，不部署/不占窗。

## 1. 决策频率
- 现状：每决策按宏步推进（宏可长）；推理频率低于 62Hz。
- 目标：**62Hz 可打断决策**（每帧可重新选残差/中断宏）；
- 方案：宏 chunk（K 帧）+ 每帧残差覆盖；决策点=宏 chunk 边界或可打断点；
- 延迟预算：≤16ms/决策（62fps=16.1ms）；H1 T=16 **p99 9.85ms / p50 2.82ms**（优化后，2026-10-26 bench v2）可支撑。

## 2. 可中断宏
- 宏标注可打断点（帧/事件）；中断条件=受击/被防/对手状态突变/价值差；
- 中断后进入残差/新宏；记录中断来源；
- 防抖：最小执行 2F；中断冷却；guard 防抖。

## 3. 动作 chunk
- chunk schema：{kind, slot, frames, resid_seq, interrupt_at}；
- 执行器统一推进；与 task-73 组合动作/续接共用 schema；
- 离线基准：宏 chunk 长度分布、可打断率、帧级输入覆盖率（task-70 样本）。

## 4. 蒸馏 fast policy（备选）
- 大模型（H1/Transformer）→ 小模型（MLP/GRU）蒸馏策略+价值；
- 目标：batch1 CPU 延迟 ≤5ms；精度损失 ≤2% top1；
- 离线评估：held-out episode 行为匹配率。

## 5. 验收
- 行为测试：中断条件/可打断点/最小执行/帧级输入覆盖；
- 延迟基准：62Hz 可达（P99 ≤16ms）；
- task-70 时序可复现率 ≥98%（v1 后）；
- A/B 待批窗（单变量）。

## 6. 风险/反债
- 高频决策→CPU/延迟/抖动；chunk+蒸馏缓解；
- 中断抖动/宏稳定性；防抖与冷却；
- 与 task-73 共用 chunk schema，避免两套执行器（R16）。
