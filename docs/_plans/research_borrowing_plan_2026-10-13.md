## 1. W1 能力归因档案 — 延迟消融评估通道(最高优先)

**目标**: 同一模型快照在 k 帧观察延迟下评估, 产出"强度-延迟曲线"——
未来一切"超人"主张的前提(笔记 §四.7: 曲线斜率本身即结论)。

- **接入点**: 新增 `tools/attribution_probe.py`; 修改
  `tools/eval_matrix.py:51 run_matchup` 增加 `delay_frames=0` 参数——
  在**己方**驱动的状态读取处包一层 `DelayedView(k)` 状态延迟垫片(策略
  特征构建与事件检测消费 t-k 帧的状态视图; 计分/日志用真值不受影响);
  对手侧不延迟(测的是"我们让步多少")。延迟垫片实现于
  attribution_probe.py, eval_matrix 只传参(单一真值源)。
- **档位**(用户裁定 2026-10-13, 原文回显: "延迟80ms即可, 原文的200ms
  太夸张了"): k ∈ {0, 3, 5, 8} 帧(≈0/48/81/129ms@62fps), **主档 5 帧
  (≈81ms)**。文献 230-240ms 仅作外部参照留档, 不作本项目包络。
- **作用域声明(v2, 审查②)**: 延迟垫片作用于**全管线**——特征构建、帧级
  事件检测、**以及宏执行器的门判定/中断判定**(confirm 门消费的 d_deal、
  R34/受击中止读的状态全部经延迟视图)。这是有意为之的生态效度选择:
  人类的"确认感"与"被打感"同样有反应延迟, 纯感知延迟口径会低估真实
  让步。报告与一切对外的曲线引用必须注明"全管线延迟"口径; 与文献对照
  时注明口径差异。**曲线斜率的解读包含门误触发的宏截断贡献**——这是
  特性不是 bug, 但报告须区分陈述。
- **样本量与 CI 修正(v2, 审查①)**: 原验收"≥40 局/对位 × CI 宽<0.25"
  存在算术矛盾(n=40、p≈0.5 时 Wilson 区间约 [0.35,0.65], 宽度≈0.30,
  **均衡对位必违反自家验收线**)。修正为: **≥60 局/对位**(p=0.5 时
  Wilson 宽度≈0.25 达标); 若某对位实测 |p-0.5|>0.2 可允许 40 局
  (非均衡时 CI 自然收窄), 但报告须标注各格实际 CI。
- **减配试点(v2)**: 首跑不做全矩阵——**1 角色(reimu)×2 对手池快照
  ×4 档 ×60 局 = 480 局**(约 8-16h 评估墙钟, probe 端口+错峰下可控);
  曲线形态确认有效后再扩三角色全矩阵(6 对位×4 档×60 局=1440 局, 二期)。
- **工作量**: 2-3 人日(垫片 1 + eval_matrix 接线 0.5 + 报告输出 0.5 +
  测试/变异 0.5)。
- **回滚**: eval_matrix 缺省 delay_frames=0 逐位等价(回归线); 垫片独立
  模块可整体摘除。
- **制度对齐**: 新模块+新调用方配对集成测试入 C15; 变异钉(把 k 帧垫片
  改成 k+1 → 曲线断言必须红); 门禁全绿后提交。
- **风险表(v2 增补后)**: ①状态延迟垫片与帧级事件(frame_events)交互
  改变掩码时序 → 设计上事件检测消费同一延迟视图(一致延迟), 测试断言
  延迟下事件数单调不增; ②与在跑 fleet 抢 CPU → 用 probe 保留端口段+
  错峰(先例: expert_harvest 与 fleet 并存 tps 预算); ③(v2)**门误触发
  级联**——延迟下 confirm 门 4 帧窗内 d_deal 晚到 → 宏截断率上升, 若
  某 k 档出现行为坍塌(胜率骤降>40pp)先查截断率仪表再下"感知弱"结论;
  ④(v2)延迟视图与 hitstop 冻结判定的交互——frozen 信号本身延迟后,
  宏队列在"实际已冻结"期间继续推进 k 帧, 属作用域内但需在报告中量化
  (可从宏截断日志推)。

## 2. W2 反事实危险显影卡(第二优先)

**目标**: 局面→强制替代宏→N 次续演→结果分布对比(笔记 §七"危险显影卡"
最小版; 宏动作天然规避 §7.6 单帧替换失真)。

- **阶段 0(可行性探针, 0.5 人日)**: 验证 `branch_demo.setup_scenario`
  能否从 episode/rep 重建观测到的关键局面(位置/血量/灵力/卡牌)。
  **若不能**(场景 API 只支持合成位置): 回退设计 = 回合起点重放至第 F 帧
  (oracle staged rep 慢放到 F 后切锁步), 复用 `run_one` 的
  TrainerClient 通道; 两案均不通则 **[用户裁定项 B]** 是否立项 mod 侧
  状态注入(走血统流程, 工作量另议)。
- **阶段 1(1.5-2 人日)**: 新增 `tools/danger_reveal.py`: 输入(局面, 实际
  宏, 替代宏, 对手规格, N≥20) → 续演分布(胜/负/伤害分布/危险兑现率)
  + 对比表(实际 vs 替代); 输出结构对齐"危险显影卡"字段(局面/实际/
  诱人替代/惩罚条件/概率/人类条件标注列暂空)。
- **续演随机源规定(v2, 审查③)**: 确定性锁步 = 同种子同状态同输入 → 同
  轨迹。N 次续演若不注入受控随机性就是 1 个结果重复 N 遍。**随机源
  必须显式指定且可复现**: ①策略采样(评估温度 ≥0.5 时的采样熵);
  ②对手快照轮换(每局从对手规格 ≥2 候选中换); ③种子 = hash(局面,
  替代宏, 副本序号)——三源至少启用两项。**分布非退化为硬验收**:
  N≥20 次续演须出现 ≥2 种不同终局(胜/负/不同 KO 回合), 否则该批次
  作废重跑(随机源失效的运行时检测)。
- **阶段 2(1 人日)**: 与 habit_punish_demo 教学闭环对接(习惯→其替代
  路线的危险分布)。
- **回滚**: 纯新增工具, 无训练面改动; 阶段间独立。
- **制度对齐**: 集成测试(合成必败分支检出率)+变异钉; 归因隔离纪律
  (观测工具不触训练, 先例 B3)。
- **风险表**: ①强制偏离后原策略分布外崩溃被误读为"路线危险"(笔记
  §7.7)→ 报告区分"原策略接管/该路线专家接管"两种续演, 首版至少标注
  接管者; ②单一对手规格的稻草人风险(§7.4)→ 对手规格必须含 ≥2 风格
  (对手池快照+COM)才可出报告; ③(v2)**续演退化**——随机源未生效时
  N 次续演收敛为单轨迹, 分布指标全部失真 → 分布非退化硬验收(上行)
  + 报告附各副本终局列表供人工抽查。



### W2 阶段0可行性探针结论(2026-10-13晚)

**问题**: branch_demo.setup_scenario 能否从 episode/rep 重建观测到的关键局面?

**回答: 部分可**:
| 状态量 | 可设? | 机制 |
|---|---|---|
| 位置(X/Y) | ✓ | OPCODE_SET_POSITION(双侧×4float) |
| 血量 | ✓ | OPCODE_SET_HEALTH(双侧) |
| 天气 | ✓ | OPCODE_SET_WEATHER |
| 灵力 | ✗ | 无对应opcode |
| 手牌 | ✗ | 无对应opcode |
| 技能等级 | ✗ | 无对应opcode |

**结论**: HP/位置/天气可精确重建; 灵力/手牌不可. 对"危险显影卡"
(核心: 位置+血量局面下的替代选择对比), **直接重建已够用** —
灵力/手牌在多数关键时刻影响有限(灵力通常充足时才冒险, 手牌在
压制/择场景非主导). 特殊需要全状态的场景走回退方案(回合起点
重放至第F帧后切锁步, 复用oracle通道).

**[用户裁定项B]: 不需要mod侧状态注入** — 现有opcode够用.
