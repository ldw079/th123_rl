# task-80 策略层（策略向量 z）设计 v0（2026-10-26）

> 用户问"能不能制定策略而非只做逐键决策"；现状=无显式策略/意图层，PPO 在宏决策点直接输出动作，
> 行为高被动（远弹 77–90%、approach 8–16%），无显式推板/爆灵目标。

## 1. 策略向量 z（可解释、用户可控）
- 维度（示例）：进攻性、目标偏好（推板/爆灵/伤害/资源）、距离偏好、资源策略（卡/灵）、风险；
- 每维 [0,1] 或离散档；默认中性；用户/教练可设；
- 记录 z 与行为指标，支持 R19 验收（不同 z 行为可测差异）。

## 2. 条件化设计（候选）
- A. **z-conditioned RL**：z 作为策略输入/条件，训练采样 z；推理时用户设 z；
- B. **层次策略 tactic + N 决策**：高层选 tactic（压/退/推板/爆灵），低层宏/残差执行；
- C. reward weights 课程：按 z 调奖励权重（推板/爆灵/伤害）；
- D. 人类标签辅助（task-74 地基+批后才用，**不提前**）。
- 首选 A+B 组合（z 条件 + 显式 tactic），C 作训练课程；D backlog。

## 3. 策略标签与指标
- 进攻性指数（前压/攻击按键率）；corner carry 率；爆灵次数/收益；资源使用率；压制时长；
- 每 tactic 胜率/伤害/被确反；z→行为一致性（可测差异）。

## 4. 用户接口（R19）
- 用户/教练设 z（GUI/配置）；验收=不同 z 行为可测差异 + 回放；
- 首个验收包：z=进攻 vs 保守 两档，对比回放/指标。

## 5. 实现阶段
- 设计+离线原型（用现有 episodes 推断 tactic 分布基线，1–2 天，不占窗）；
- 策略层→条件化训练→window→人测；与 task-73/77/79 对接；
- 风险：z 与 PPO 冲突/策略抖动/验收主观；反债：z 定义一次、registry 化；不建旁路。
