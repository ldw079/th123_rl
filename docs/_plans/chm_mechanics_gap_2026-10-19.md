## 1. P0 补充细节（给现有任务的关键修正/输入）

### 1.1 DD（回避结界）——task-28
- **使用条件**：自身处于**正确防御的防御硬直中**（防错不可）、不在 HITSTOP 中（防御成功的瞬间不可）、不在 SC 暗转结界中；至少 1 个正常灵力珠（快晴除外）。
- **输入**：方向 + DD；**15F 输入缓冲**，HITSTOP 中可提前 15F 输入但要等 hitstop 结束才发动；发动方向取发动前 1F 输入方向；无方向默认 **4 方向**（地面/空中皆可）。
- **方向差异**：地面 4DD 带完全无敌；地面 6DD/1DD/2DD、空中 4/6DD 只有 GRAZE 无打击无敌；空中没有 7/8/9/1/2/3DD；地面没有 9DD。
- **代价**：破坏 1 灵力珠 + 灵力回满（快晴不破珠也不回灵；太阳雨破珠≈瞬间修复）；因此 DD 是"用灵珠换位置/脱离"，不是白嫖。
- **对训练**：DD 宏只在正防硬直 unmask（task-28 已做）；但"提前 15F 输入"与"方向取发动前 1F"必须由执行器时序支持（task-30 的 buffer 原语）；建议 DD 宏前加 `hold_guard` 或让 mask 只在"防御硬直中"放行（当前 task-28 用 150-167，符合）。
- **缺口**：task-28 目前只做"门控"，未做"DD 的使用激励"（DD 破珠代价 vs 位置收益）；且 DD 宏在 hitstop 中的预输入需要执行器支持。

### 1.2 天气——task-31（补充机制）
- **预报轮换**：出现 **倒地/弹地/弹墙 或 使用 SC** 时，预报按下表顺序前进一次 → **控天的核心动作是"通过倒地连段/SC 使用管理预报"**，不是随机。
- **天气玉读数**：发动前 0.1/F 增加（0→99.9 需 16.6s）；发动后 0.2/F 减少（99.9→0 需 33.2s）；部分天气起始 49.9/74.9；天气中某些行动会额外减少。
- **发动**：读数满 99.9 自动发动预报；或 **绯想剑**（系统卡）直接发动预报并从 99.9 起算。
- **天气效果表**（20 种，全表见 corpus）：快晴（飞耗灵减半/DD 不破珠）、雾雨（SC×1.25）、曇天（SC 耗-1/集卡×2）、苍天（必杀互相取消、耗灵递减）、雹（必杀×1.25/回灵×2）、花曇（打击可 GRAZE/射击附磨耗）、浓雾（吸血 50%）、雪（打中削卡）、天気雨（防错直接破防/DD 不破珠/珠修复快）、疎雨（必杀 LV MAX）、风雨（空中行动 3 次/水平加速）、晴岚（卡片遮蔽/可无视消耗用 SC）、川雾（吸斥力）、台风（刚体/不能防）、凪（最后命中者回血）、冰晶（倒地+500/不可移动起身）、黄砂（全 COUNTER/首 HIT 追击×2）、烈日（高空掉血换攻/符力）、梅雨（倒地弹墙回转/弹地可追）、极光（随机天气隐藏）。
- **模型缺口**：只有当前天气 ID + timer；无预报、无气质计数、无"天气效果→对策"的表征；无"通过倒地/SC 控预报"的意识；`卡·绯想剑` 宏存在但使用率 0.006-0.014%。

## 2. P1 新立项（task-32/33/34）

### 2.1 task-32 防御取消体系（铜钱/羽衣/灵击/DD）
- **铜钱（宵越しの銭，系统卡 id 12）**：仅**正确防御的防御硬直**中可用（防错/HITSTOP 不可）；消耗 1 灵力、不耗卡；把对手弹开 1 身位；版边对打击无效；每防 1HIT 只能用 1 次；手牌铜钱越多回灵冷却越短（140/120/100/80F）。
- **羽衣（龍魚の羽衣，系统卡 id 14）**：仅正防硬直中；11F 暗转后反击（发生 28F/全体 62-65F）；完全无敌到判定出现；被防硬直差 ≤-10F。
- **灵击（霊撃札，系统卡 id 0）**：完全无敌凹，吹飞近身，被防/落空硬直大易被确反。
- **现状**：这些宏都在（`卡·铜钱/灵击/羽衣?`——注意：宏名有 `卡·铜钱`、`卡·灵击`，未见 `卡·羽衣`；需确认 21 系统卡中哪些有宏，缺的补宏）。使用率极低（铜钱 0.014-0.166%、灵击 ≤0.0165%），且**无正防态/灵力/手牌门控**→ 选了也发不出或浪费。
- **方案**：a) 给系统卡宏加状态门控（铜钱/羽衣→正防硬直；灵击→受击/压制可选但保留泛用）；b) 使用激励（成功弹开/反击/凹到 给小额奖；失败按空挥/被确反罚）；c) 缺失系统卡宏补齐（羽衣等）；d) 诊断：使用率/成功率/被确反率；e) 与 task-28/29/30 的 mask 层统一，不另起一套。

### 2.2 task-33 连段/帧数据优化

### 2.3 task-34 受身/起身/推板/移动技巧
- **受身**：被吹飞、追击时间结束、无保护结界时 4/6+任意键，15F 完全无敌；弹地瞬间不可受身；梅雨 7F 强制弹地；不受身则落地前无敌（行动解除）。

- **推板/版边**：连段/防御把对手往角落推；版边压制的套路（表择/里择、抄地、祈雨、放帧抓乱动）——模型只有空间惩罚（贴边罚、离墙奖励），没有"把对手推入角/版边持续压制"的正向目标。

## 7. 卡组/装配语义缺口（新发现，重要）

- **每局开局由 `train_tm.py:1029 sample_deck(...)` 采样卡组**（archetypes：system/skill/sc/mixed）→ **同一命令宏（如 236B/623B/214B）在不同局可能是不同技能**（默认/替补/替换），甚至某些局没有该技能卡 → 命令输入可能无效；SC 卡池也每局不同。
- 但：a) **mask/reach/startup 表是静态的**（`reach_maps` 按宏名/默认技能），不随卡组变化；b) 特征只有手牌/已出卡/符力，**没有"本局装备的技能变体/卡组构成"**；c) BC 语料中的宏标签来自特定卡组，命令语义可能不一致。
- 后果：动作语义非平稳（同动作→不同效果）、掩码允许不可用技能（选中=空转）——**这可能与"指令技低触发率"直接相关**（audit：reimu 623B 只 ~14% 出现 B/必杀、suika 623C 2.2%）。
- 建议（P1，**task-35**）：①训练期卡组固定/按流派分桶（或至少固定主训练卡组，评估用多卡组）；②特征加"本局卡组/技能装配"（可低维：archetype one-hot + 已装备技能 id 位图/槽位）；③mask 按装配动态（技能卡是否在卡组；命令映射到当前技能）；④BC 标签按卡组对齐；⑤后续再评估"选卡组"作为动作（P2）。
