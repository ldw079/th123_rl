### 变招行为（对"专门反制你"的对手测量）

| 行为 | 人类描述 | 可测判据 |

| B1 短期回避 | 跳了两次被对空 → 不跳了 | 跳跃类使用率被 punish 后 3 局内降至 <50% 原频率 |

## 2. 方案主体——八件套（S-1~S-8, 统一编号）

### 基础层（先建共享基础设施）

#### S-1 · MyPunishTracker（共享组件, 1.5 人日）

**新增 `my_punish_tracker.py`**——"我方招式类别 × 被反制结果"的滚动 EMA:

```python
class MyPunishTracker:
    """双方通用(我方在线 + 专家后处理共享同一实现).

    类别: JUMP / MELEE / BULLET / SKILL / GUARD_PREP / OTHER
    结果: PUNISHED(我出招→被对手命中且我未命中) / WHIFFED / NEUTRAL / LANDED
    输出: 每类 punish_rate ∈ [0,1] (EMA 半衰 ~30s)
    """
```

punish 判定:
```
我方类别 C 的宏在执行
  && 对手命中我方(d_take>0 且对手在攻击态)
  && 我方未命中(d_deal==0)
  → C 类 punish+1
(被防无伤=NEUTRAL 不算——被防≠吃亏)
```

**两个消费者**:
- **在线**（train_tm 帧循环）: 每决策点 `tracker.update(dec_class, outcome)` → 特征侧实时读;
- **离线**（P-2 的后处理脚本）: 对 oracle shard 双边逐帧重放 → BC 行获得专家 punish 标注。

**验收**: 合成"连续跳跃被对空"→ jump_punish_rate>0.6; 行为测试。

#### S-2 · 特征追加 +12 维（一次 CORE_DIMS 迁移, 1.5 人日）

**CORE_DIMS 330 → 342**, 侧向量追加:

| 维 | 来源 | 内容 | 归一 | 服务 |
|---|---|---|---|---|
| 1-4 | S-1 在线 | jump/melee/bullet/skill punish_rate | [0,1] | 变招 B1-B4 |
| 5 | V-2 aux 回流 | my_predicted_class（top-1 类压缩） | /8 | 预测→反制接口 |
| 6 | V-2 | my_predicted_conf（top-1 置信度） | [0,1] | 同上 |
| 7 | P-2 | same_streak（当前标签类别连续出现次数） | /5 clip | 防预判 |
| 8 | P-2 | recent_entropy（最近 5 招多样性） | /log(5) | 出招多样性 |
| 9 | P-2 | is_switch（本行是变招） | 0/1 | 换招标记 |
| 10 | P-2 | opp_punish_my_dominant（对手 punish 我主导类率） | [0,1] | 被反制感知 |
| 11-12 | S-7 风格嵌入 | style_pc1 / style_pc2（16 维嵌入的 top-2 主成分） | [-1,1] | 风格条件化 |

**实施**: 常量横扫 SOP（BC 库 repad + 模型迁移 + 门禁布局 + onestep 等价先行）。

### 记忆层（依赖 S-1/S-2）

#### S-4 · GRU 对手+自我序列记忆（V-3, 4 人日）

- **输入扩展**: 原 75 维对手切片 → **87 维**（+6 punish +2 预联回流 +4 反重复）——GRU 同时记忆"对手在做什么""我被怎么反制""我最近在重复什么"；
- **隐状态**: 16→**24** 维;
- **BPTT 窗口**: **近 3 场**（变招因果链需跨局）;
- **可重放设计**: 沿用系列方案 §5（GRU 输入 = 侧向量切片, 可从存储 sides 完整重放）;
- **双梯度源**: RL 对局梯度 + BC 专家序列梯度（P-3）共同回流;
- **系列内隐状态携带**: SeriesManager 管控扩展到 GRU state。

**验收**: onestep 等价含 GRU; 合成"3 场持续对空"→ 第 3 场跳宏采样率 < 第 1 场。

### 专家数据层（依赖 S-1, 独立于 S-3/S-4 可先行）

**后处理脚本 `tools/expert_punish_track.py`**: 对 191 shard 双边逐帧跑 S-1 的 tracker → shard 附加 punish 列（EP_SCHEMA 2→3）。

**bc_build 追加特征**: 维 7-10（S-2 表）——`same_streak`/`recent_entropy`/`is_switch`/`opp_punish_my_dominant` 从 matcher 输出序列 + 后处理 punish 列计算。

#### S-6 · BC 序列感知采样（P-3, 0.5 人日增量）

`_sample_bc()` 从 iid 改为连续窗口（同一 shard 内连续 64 个决策点）; BC 库追加 `shard_id` 列; GRU 路径接入（与 S-4 共享参数）。

### 风格层（依赖 S-2, 可与 S-4 并行）

#### S-7 · 风格连续嵌入 + 条件化（P-4 重设计, 2.5 人日）

**A. 风格嵌入提取 `style_embedding()`（0.5 人日）**:
- **不是分类**——从既有 opp_model 75 维 + feat_builder B 段 14 维压缩为 **16 维连续嵌入**:
  - 情境矩阵主成分 8 维（PCA 压缩 9×8, 保留情境轴不做全局平均）
  - drift 1 维（风格变化率）
  - 资源条件差分 4 维（灵满-灵空的行为差 → 资源依赖风格）
  - 卡组暴露 3 维（B 段压缩）
- **连续**: 16 维向量, 无离散边界; **情境依赖**: PCA 保留情境轴; **动态**: 随 EMA 演化; **关系性**: 距离/情境轴天然嵌入双方位置。

**B. 风格条件化标准树（1 人日）**:
- 每个既有树节点增加 `f(style_vec, 宏) → 权重` 的线性回归器;
- 审计输出从"模型 vs 标准"二元偏离 → "模型 vs **风格条件化标准**"的残差（偏离有了风格归因）;
- **不做**"偏攻时标准 X / 偏防时标准 Y"的离散分层。

**C. 教学讲解风格个性化（0.5 人日）**:
- teach.py 讲解含风格描述（嵌入→自然语言的投影, 投影≠定义）;
- "对这种风格的对手, 标准偏好是 X（占比 50%）——你选了 Y（偏离）"。

**D. BC 标签风格条件（0.5 人日）**:
- S-2 的第 11-12 维 = 嵌入 top-2 主成分（不做全 16 维——BC 库宽度已够, 2 维投影保留主要方差即可; 全 16 维经 GRU 路径隐式可用）。

#### S-8 · 变招压力测试环境（V-4, 1.5 人日）

**新增 `tools/adaptation_probe.py`**:
- **规则反制者**: SideDriver 的 frame_input 加"反制偏好"——追踪我方最近 20 决策主导类别 → 该类被反制概率提升;
- **剥削者版**: league exploiter 快照;
- **输出**: 逐场宏分布演变 + punish 率轨迹 + B1-B4 行为标记 + 风格嵌入轨迹（S-7 联动——压力下的风格演化可视化）。
