# 变招能力完备方案——从隐式统计到显式战略切换（2026-10-14）

> 需求: 用户问"模型能否做到人类式吃亏后积极变招"→ 分析结论: 三层中仅层1(战术反应)完备, 层2(统计感知)隐式弱连接, 层3(策略切换)结构性缺失 → 用户令"给出完整可行性方案，以最终效果优先，不需要特别考虑工作量"。
> **效果优先原则**: 每一档设计都以"人类高手会怎么做"为标尺, 不因工程量妥协; 工作量作为参考标注但不作为裁剪依据。
> 合规: PLANNING_AGENT.md 三段式。

## 1. 效果标尺——"人类式变招"拆解为可验收的行为

| 行为 | 人类描述 | 可测判据 |
|---|---|---|
| B1 短期回避 | "跳了两次都被对空 → 不跳了" | 跳跃宏使用率在被对空 punish 后 3 局内显著下降（<50% 原频率） |
| B2 替代路线涌现 | "不跳后 → 地面压制变多" | 压制/近战宏使用率上升, 且与 B1 同期 |
| B3 反预期利用 | "他等我跳 → 假跳骗对空 → 抓落地硬直" | 对空 punish 率下降后, 跳跃宏使用率**回升**（非单调回避） |
| B4 整套切换 | "空压打不动 → 换地面立回" | 特定场景（如对手对空强）下的宏分布整体偏移, 非单宏替换 |
| B5 跨局记忆 | "上局他防住了我全部压制 → 这局一开始就换" | 首局 vs 后续局的宏分布差异（系列位置敏感度） |

**总验收**: 对一个"专门反制我方当前打法的剥削者", BO15 系列中模型在第 3-5 局完成 B1+B2（回避+替代）, 第 5-8 层出现 B3（反预期）或 B4（整套切换）。

## 2. 方案主体——五件套（效果优先, 从基础设施到行为涌现）

### V-1 · 我方失败追踪器（V1 层 2 显式化, 1.5 人日）

**新增 `my_punish_tracker.py`**——与 opp_model 对称的"我方招式被反制统计":

```python
class MyPunishTracker:
    """我方招式类别 × 对手反制结果的滚动 EMA.

    类别: JUMP(跳跃/空翔/高跳), MELEE(近战/连段/压制),
          BULLET(弹幕), SKILL(必杀), GUARD_PREP(防御), OTHER
    反制: PUNISHED(我出招→被对手命中/被防不利),
          WHIFFED(空挥), NEUTRAL(正常执行), LANDED(命中对手)
    输出: 每类一个 punish_rate ∈ [0,1] (最近N次的EMA, 半衰~30s)
    """
```

**特征追加（+6 维, CORE_DIMS 330→336）**:
| 维 | 内容 | 归一 |
|---|---|---|
| jump_punish_rate | 跳跃系被反制率 | [0,1] |
| melee_punish_rate | 近战系被反制率 | [0,1] |
| bullet_punish_rate | 弹幕系被反制率 | [0,1] |
| skill_punish_rate | 必杀系被反制率 | [0,1] |
| my_predicted_class | aux 头当前预测的对手下拍类 | one-hot 压缩 /8 |
| my_predicted_conf | aux 预测置信度（top-1 概率） | [0,1] |

后两维实现**预测回流**（V-2 的一部分, 合并追加）。

**归因逻辑**——punish 的判定:
```
在决策→决策窗口内:
  我方类别 C 的宏在执行
  && 对手命中我方(d_take>0 且对手在攻击态)
  && 我方未命中(d_deal==0)
  → 该类别的 punish 计数 +1
  (被防但无伤 = NEUTRAL, 不算 punish——被防≠吃亏)
```

**接线**: train_tm 帧循环中已有的 `dec_name/dec_dmg/dec_guarded` 状态可直接消费, 在决策点调用 `tracker.update(dec_class, outcome)`; feat_builder.build() 读取 tracker 输出。

**验收**: B1 可测——合成"连续跳跃被对空"序列 → jump_punish_rate 达到 >0.6; 行为断言: 该特征值>0.5 时策略采样分布中跳跃宏的概率显著下降（需训练, 断言改为"特征存在且非恒零"——训练后效果由 V-6 验收）。

### V-2 · aux 预测分布回流（V1 预测→反制接口, 1 人日）

**改动**: ppo.py 的 `sample()` / `_pi_forward()` 增加 `return_pred=True` 路径, 返回 aux 头的 softmax 分布; train_tm 决策点拿到 top-1 (类, 概率) → 写入特征的 `my_predicted_class/conf` 两维。

**效果**: 策略可直接读"对手将跳(置信 0.7)"——无需间接从共享 trunk 再发现。反制映射（"对手要跳→我出对空"）由策略学习, 但输入信号从隐式变显式, 学习难度大幅降低。

**验收**: 合成对手序列"连续跳 5 次"→ my_predicted_class 进入跳跃类; conf>0.5; 特征存在且非恒零; ppo 等价测试更新（新维度零初始化迁移, 旧策略逐位不变）。

### V-3 · GRU 对手序列记忆（V1 层 3, 4 人日）

**设计完全沿用系列方案 §5**（可重放 GRU）——此处只列差异与增量:

- GRU 输入扩展: 原 75 维对手切片 → **75+6=81 维**（含 V-1 的 punish 追踪 + V-2 的预测回流）——GRU 同时记忆"对手在做什么"和"我被怎么反制";
- **BPTT 窗口扩展**: 系列方案设计为"场内截断", 本方案改为**近 3 场窗口**——变招往往需要 2-3 局的因果链（"我跳了→被对空→我停了→他防空落空→我再跳"是一个跨局循环）;
- 隐状态维度: 16→**24**（增加的 6 维输入需要更大容量; ppo_gpu 同步, onestep 等价测试扩展覆盖 GRU 路径）;
- 系列内隐状态携带（SeriesManager 已在, 管控扩展到 GRU state）。

**验收**: B5 可测——合成"3 场持续对空"序列 → GRU 隐状态在第 3 场时跳宏采样率显著低于第 1 场; onestep 等价含 GRU 路径; 系列重置断言。

### V-4 · 变招压力测试环境（效果验收的基础设施, 1.5 人日）

**问题**: 变招能力只有在"对手专门反制你"时才能显现——固定快照对手测不出（模型已碾压, 无吃亏可吃）。

**新增 `tools/adaptation_probe.py`**:

```python
def probe_adaptation(char, games=15):
    """变招能力专项评测:
    对手 = 剥削者(针对当前模型专门训练的反制快照)
    或  = 规则反制者(检测我方最近 N 拍的主导类别 → 选招反制)
    产出: 逐场宏分布演变 + punish 率轨迹 + B1-B4 行为标记
    """
```

- **规则反制者（首版, 不需要训练）**: SideDriver 的 frame_input 内加逻辑——追踪我方最近 20 决策的宏类别 → 若某类 >50% → 该类被反制的概率提升（如我方跳跃多 → 对手多出对空）; 实现 = 在 reaction_mask 或 frame_event 中加一个"反制偏好"参数;
- **剥削者版（加强版）**: league 的 exploiter 快照（exploiter.py 已在, run_exploiter 可产）;
- **输出**: 每场结束打印"本场宏类别分布 + 各类 punish 率", 15 场后输出"分布演变曲线"（B1-B4 的直观呈现）。

**验收**: 对规则反制者, 15 场内可观测到 B1（跳跃类使用率下降）+ B2（替代类上升）; 剥削者版作为长期追踪。

### V-5 · 变招奖励塑形（可选, 慎用, 0.5 人日设计 + 观察评估）

**原则**: 变招最好是**涌现的**（策略学会读 punish 特征后自然变招）而非**强制的**（奖励直接驱动变招）。因此本项为**可选附加**, 仅在 V-1~V-3 落地训练 2 周后 B1-B4 仍不涌现时启用。

**设计（备而不用）**: 势函数加一项——`punish_rate 高的类别, 使用该类宏的势差额外扣分（×0.001, 量级低于 KO±10, 与"塑形只用正向"定律的张力→改为"低 punish 类使用加正分"而非"高 punish 类扣分"）。

**验收**: 启用后 B1 曲线斜率显著改善; 副作用（过度回避→全防御）通过 passive 仪表监控。

### V-6 · 训练整合与总验收

**训练侧接线**（V-1/V-2/V-3 共同落地后）:
1. CORE_DIMS 330→336（常量横扫 SOP: BC 库 repad + 模型迁移 + 门禁布局断言）;
2. GRU 参数入 ppo.py/ppo_gpu.py 的 init/load/save/迁移链;
3. 侧向量 `n_side = 5N + 336`;
4. onestep 等价测试覆盖新维度+GRU;
5. fleet actor/learner 的 sides 维度自动跟随（派生式已在）。

**总验收**（对 V-4 的规则反制者, BO15 × 3 系列）:

| 行为 | 判据 | 通过线 |
|---|---|---|
| B1 短期回避 | 主导类 punish 率>60% 后, 该类使用率 3 局内降至 <50% 原值 | ≥2/3 系列 |
| B2 替代路线 | 与 B1 同期, 替代类使用率上升 ≥30% | ≥2/3 系列 |
| B3 反预期 | punish 率回落后, 原类使用率**回升** | ≥1/3 系列 |
| B4 整套切换 | 宏分布余弦距离（首局 vs 第 10 局）>0.3 | ≥1/3 系列 |
| B5 跨局 | 首局 vs 后续局的宏分布显著不同 | 系列位置敏感度>0 |
| 无退化 | 顶时判负率/净分无恶化 | passive 仪表 |
| 门禁 | 全绿 + 变异覆盖新断言 | contract_check |

## 3. 排期（总计 ~9 人日, 效果优先不设并行限制）

```
第 1-2 天: V-1 失败追踪器 + V-2 预测回流（+6 维, CORE_DIMS→336, 全链路更新）
第 2-3 天: V-4 变招压力测试环境（规则反制者首版）
第 3 天  : 基线测量（V-1/V-2 落地但未训练——当前模型在压力测试下的 B1-B4 基线）
第 4-7 天: V-3 GRU 序列记忆（81 维输入, 24 隐状态, 3 场 BPTT, 等价测试）
第 8 天  : 训练整合 + CORE_DIMS 迁移 + 门禁全绿
第 9 天  : 首轮 V-6 总验收 + 基线对照
持续    : 每日 fleet 训练 + 每周 V-4 压力复测 → 观察 B1-B4 涌现
两周后  : B1-B4 未涌现 → 评估启用 V-5 塑形
```

**依赖关系**: V-1/V-2 先于 V-3（GRU 输入包含它们）; V-4 先于 V-6（验收需要它）; V-5 最后（备而不用）。
**与系列方案的关系**: V-3 的 GRU 与系列方案阶段 3 是同一组件——**合并实施**（一次改动同时服务"系列内适应"和"变招记忆"）; 排期对齐。

## 4. 风险表

| 风险 | 概率 | 缓解 |
|---|---|---|
| punish 特征被策略忽略（学不到关联） | 中 | V-2 预测回流使信号更显式; V-4 压力环境强制暴露; V-5 塑形兜底 |
| GRU 训练不稳定（序列记忆难学） | 中 | 场内 BPTT 保守起步（先 1 场, 逐步扩到 3 场）; aux 损失作为稳定锚 |
| 变招 = 过度回避（从被动到全防） | 中 | passive 仪表实时监控; B3（反预期）作为"非单调回避"的验收项 |
| CORE_DIMS 迁移事故（308→316→330→336 四次前科） | 中 | 常量横扫 SOP 强制 + learner 派生式在 + onestep 等价先行 |
| GRU+变招特征使 fleet 中途态复杂化 | 中 | EP_SCHEMA 版本化在; actor 崩溃=丢系列记忆（与人类断线同构, 已有先例） |
| 规则反制者太弱（测不出真实变招需求） | 低 | 剥削者版作为加强; 真人测量（B 通道）作为终极标尺 |

## 5. 不变面

- 奖励结构（除 V-5 可选项外零改动——变招是策略层的适应, 不需要奖励层的激励重构）;
- 宏名/动作空间/掩码/分支门——变招在策略选择层面发生, 宏库已提供多样化选项;
- R1-R11 红线 / fleet 三红线 / 单写者 / 门禁纪律;
- BC 锚退火路径（变招与模仿不冲突——锚随退火归零已在）。
