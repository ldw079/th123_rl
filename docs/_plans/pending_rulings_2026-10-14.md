## 裁定一: P2 同形宏组标签语义(审计2026-10-14立案, 5组)

**公共背景**: 离线BC标注只能看输入流。这5组宏的**可匹配前缀**输入
完全相同 → 标签按库序任意归属, 实测系统性偏向组首(连段B/C恒0)。
但深入看, 5组的"不可分原因"分两类, 对应两种修法:

- **类甲(confirm门族, 4组)**: 差异在confirm门**之后**, 门后输入
  实际**可分**(6A/DA/2B输入不同) — 匹配器只匹配门前前缀所以看不到。
- **类乙(纯同输入, 1组)**: 后退/立防 整段输入全同, 只有**对手
  攻击态**可分(对手出招时的back-hold=格挡)。

### 组1: 连段A/B/C/版边连A(类甲)
- 脚本: 前9步完全相同(A,confirm门...)。门后: 连段A→6A
  (right×6+rightA); 连段B→DA(right**D**×6+rightA); 连段C→2B
  (down×6+downB); 版边连A→B+C续。
- 实测: 连段A 22 / B 0 / C 0 / 版边 0 — **门后分支全被吞**。
- 语义: 同一起手命中后的不同终结分支(位置/伤害/资源取舍)。
- 选项:
  - **A 门后窥视(lookahead)**: 门前缀命中后向前看12-20帧,
    与各分支门后输入比对, 归属最吻合者; 无后续输入(对手格挡/
  挥空, 门未confirm)则标"起手"或丢弃。精度高, 中等工作量。
  - B 组内合并: 标签统一为代表宏, BC不教分支偏好, PPO自己选。
    零风险, 丢专家分支知识。
  - C 维持现状: 标签系统性偏组首(最差, 不建议)。
- **建议: A**(门后输入确可分, 且回收的是连段终结的专家偏好)。

### 组2: 2A / 2A确认 / TM·2a连(类甲)
- 脚本: 2A=[down6,downA10]; 确认版=2A+confirm+门后downB等;
  TM·2a连=2A+confirm+()9+downB+C…(节奏差9帧+后续C)。
- 实测: 2A 0 / 2A确认 137 / TM·2a连 0 — 确认版吞了裸2A
  (库序+前缀同形)。
- 语义: 裸2A( Poke ) vs 2A命中接下段连段 vs 慢节奏版连段。
- 选项同组1(A门后窥视/B合并/C现状)。
- **建议: A**。注意裸2A与确认版的区分=门后**有没有**后续
  (无后续→裸2A), lookahead天然覆盖。

### 组3: 5A / 5A确认(类甲)
- 实测: 5A 335 / 5A确认 17。
- 同组2构型。**建议: A**(同上)。

### 组4: jA / 空连A(类甲)
- 脚本: jA=[up6,A10]; 空连A=jA+cconfirm+空中续连。
- 实测: jA 2 / 空连A 0。量小(空中A多走连段A系)。
- **建议: A**, 顺带; 或B(量小不值得)皆可接受。

### 组5: 后退 / 立防(类乙, 审计续③新增)
- 脚本: 后退=[left×6]; 立防=[left×12] — 当前按保持时长
  机械区分(实测 后退95 / 立防825)。
- 语义: 走后撤 vs 格挡, 输入全同, **仅对手攻击态可分**。
- 选项:
  - **A 状态上下文标注**: rep状态帧里有对手action字段 —
    对手攻击/命中窗口内的back-hold标立防, 其余标后退。
    需要把对手action传进匹配循环(实现中等)。
  - B 维持时长区分(现状): ≥12帧=立防。错分方向已知
    (长走后误标立防), 但两者都是防御性行为, 先验污染有限。
  - C 合并为一族。
- **建议: A**; 若嫌工程量, B可先接受(错误是防御类内部的混淆,
  对"拉防极弱"的治疗影响小)。
