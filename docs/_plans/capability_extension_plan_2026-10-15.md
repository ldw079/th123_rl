### 1.2 关键使能事实（决定方案形态）

**侧向量已是"逐宏元数据块"架构**（train_tm.py:787-811，n_side=5n+CORE）：

| 块 | 内容 | 模式 |
|---|---|---|
| [0:n] / [n:2n] | last_macro / last_macro2 one-hot | 记忆 |
| [2n:2n+CORE] | core 特征 | 状态 |
| [2n+CORE:3n+CORE] | **射程差** clip((adx−reach_i)/200)×mask | 逐宏元数据 |
| [3n+CORE:4n+CORE] | **纵向射程差** clip((ady−reach_v_i)/200)×mask | 逐宏元数据 |
| [4n+CORE:5n+CORE] | **untech−startup_i 差**（正=来得及，目押感知基础） | 逐宏元数据 |

R24/R25 的设计原话："每个宏的 logit 可读自己的 gap（经 W_side 近对角映射），
空挥惩罚提供梯度教它读"——**CE-1/CE-3 的新块沿用这个已验证模式**，不是
新架构。

**迁移成本项**（扩块的代价，须入账）：
- BC 库宽度 assert（train_tm.py:824-826）：n_side 变化 → BC 库需重跑
  repad 脚本（既有流程）；
- 侧槽位插入迁移通道已在位（ppo.py:292-297）；
- macro_reach 的数据管线先例：mine_input_moves.py 从专家输入挖
  move_hints（射程提示）→ reach_maps.py 映射宏末攻击步——**位移挖掘
  可直接延伸此管线**。

**数据源现状**：
- oracle_v2 双边分片（专家，~750）：状态流+ilog，位移统计/实体语义
  探针的全部原料；
- 自打侧：**无逐帧持久化**（CE-0 要补的第一个前提）；
- 权威帧数据库（cleista，R111 裁定）：帧数/优势/属性窗——不含位移，
  位移只能统计法或 XML（待验）。

## ② 可执行方案（CE-0..CE-6）

### CE-0 数据前提探针（0.5 天）— 三项前置判定

1. **自打逐帧日志开关设计**（CE-6/CE-3 的前提）：训练循环加轻量持久化
   ——每局一个 npz：逐帧 (left/right 关键字段, objs 原始元组, 我方宏
   决策序列+决策帧号)。体积估算：~2000 帧/局 × ~120B ≈ 250KB/局，
   滚动保留最近 N=500 局（~125MB 上限，磁盘纪律内）。开关默认关，
   fleet 抽样开（每 actor 每 M 局存 1 局，避免 IO 影响吞吐）。
2. **XML 位移可用性**：抽 suika 一个 move 的 movepattern XML，确认有无
   每帧位置/位移字段——有则位移表走 XML 权威源；无则统计法（预期
   大概率无，R24 当年只取了 hit.box）。
3. **objs type 字节语义**（扩展 JZ-0 同批）：oracle 分片上统计首字节
   （signed b）取值分布 × 角色对照（**爱丽丝分片的人偶应呈独立 type
   簇**；萃香 22B 地雷/天子柱等设置物同理）→ 语义分桶表。

产出：探针报告 + 自打日志格式定稿 + type 分桶表。
**门规则**：type 无法分桶（分布无结构）→ CE-2 降级为"实体计数+
最近实体距离"无类型版；XML 无位移 → CE-3 纯统计法（不影响成立）。

### CE-1 招式级反制画像（1 天）

**目标**："5B 被对策了就避用 5B"——把 S-1 的类别粒度下探到宏粒度。

1. **MyPunishTracker 扩展**：begin(cls) 加宏名参数 → 双层结构——
   类别层（现状不动，特征 [330..333]/[339] 保持）+ 宏层（per-macro
   EMA，键=宏名）。API 向后兼容（name=None 时行为不变）。
2. **稀疏性处理（核心设计）**：宏层样本远稀于类别层——
   - EMA 半衰延长：类别 ~30s → 宏层 ~3min（跨多局累积，与 B5 跨局
     携带语义一致）；
   - **分层回退先验**：宏层样本数 < 阈值（如 3 次）时，块值 = 类别
     率填充（中性起点，不造没有的数据）；
   - 未执行宏 = 0（先验中性）。
3. **侧向量第 6 块**（[5n+CORE:6n+CORE]）：per-macro 惩罚率 ∈[0,1]，
   与射程差块同构——每个宏的 logit 直接读到"我最近用这招被反制多
   少"。n_side: 5n+CORE → 6n+CORE。
4. **S-5 离线后处理同步**：专家 shard 重放驱动同一 tracker（宏名来自
   StreamMatcher 标签），离线/在线同构。
5. **迁移**：BC 库 repad（新块零填充即可，语义向后兼容——旧库行没有
   惩罚历史，填类别率或 0）；侧槽位插入迁移；test_gpu 等价测试同步。

### CE-2 设置物/人偶实体语义（1 天，取代 JZ-5 对应登记行）

1. **跨帧实体跟踪**：objs 位置连续性聚合（帧间最近邻匹配，阈值 ~30px/
   帧），实体生命周期表（出现帧/消失帧/轨迹）——寿命估计天然获得。
2. **类型分桶**（CE-0.3 产出）：至少三桶——普通弹幕 / 设置物（地雷/
   门板/柱，禁入区+可被打消）/ 随从实体（人偶/幽灵，代打击+受击
   不消失）。归属（我方/对方）由分片侧+出现时机判定。
3. **特征 +4~6 维（CORE，并窗 JZ-1 的 330→362 迁移 → 362→368）**：
   - 对方设置物计数 + 最近设置物距离（禁入区信号，1/归一化）；
   - 对方随从实体计数 + 最近随从距离（代打击警示——弹幕对拼决策
     输入，与 JZ-2 相杀矩阵互补）；
   - 对方布置中标志（设置物生成前摇 = 打断窗口，配合攻略"装载窗
     惩罚"战术）；
   - 实体总寿命均值（长寿命=区域封锁型）。
4. **虚拟视觉着色（可选二期）**：类型通道区分渲染，让视觉路径也能
   学到语义。
5. 爱丽丝/天子/美铃分片为验证主力（人偶/柱/气弹设置物最丰富）。

### CE-3 宏位移表 + 压制空间账（1.5 天）

**目标**：策略在选宏时能读到"这招打完我在哪、对手被推多远"。

1. **位移统计管线**（tools/mine_displacement.py，延伸 mine_input_moves
   先例）：oracle_v2 分片上，按 action ID 出现窗口聚合——
   - Δ(own x), Δ(own y)：窗口起止自身位置差；
   - Δ(opp x)：**分桶统计**（命中桶=comboDamage 增加 / 被防桶=对手
     进入防御态 / 空挥桶=两者皆无）——推板量随结果不同是攻略明示
     机制（§8.4）；
   - 输出 data/move_displacement_<char>.json：逐 action 的
     {dx_self, dy_self, dx_opp_hit, dx_opp_block, 样本数, 方差}；
     样本 < 阈值标 low_confidence（宏使用 R24 同款保守门：低置信
     不入特征，mask=0）。
   - 宏→action 映射复用 reach_maps 管线（宏末攻击步→action ID）。
2. **侧向量第 7/8 块**（[6n+CORE:8n+CORE]）：
   - 块 7：宏后预计距离差 clip((adx − dx_opp_expected_i)/200)
     （被防语境的主导项——压制连续性信号）；
   - 块 8：宏后自身位置变化 clip(dx_self_i/200)（含版边交互的原始
     输入——配合 core 的 own_corner，网络可组合出"这招会把对手
     推向版边/把我带离版边"）。
   - n_side 最终态：8n+CORE。
3. **与 JZ-3.4 合流语义**：帧差表给"对手还能动吗"（时间账），位移表
   给"动完之后世界什么样"（空间账）——两账并排即压制账本，攻略
   "无缝矩阵（起手×后续×距离）三元组"的距离主键从此有输入。
4. **位置路由门（2026-10-15 用户批准并入）**：宏分支门语法扩展
   `pos_gate`——confirm 门命中后的续段路由加位置条件（对手贴角→
   版边路线，否则→版中路线；口径同 R23 贴角判定 x<120/>1120）：
   - macro_executor 门语法新增位置谓词（与 hit/blocked/whiff/
     opp_jump/delay_then 并列，评估时机=confirm 门通过帧）；
   - **位置自适应连段宏改造**：连段A/B/C 与版边连A 合并为
     "连段A·自适应"（版中起手→confirm→贴角走版边收尾/否则走
     弹墙推板收尾）——攻略 C5"同一命中确认因屏幕坐标不同有
     三套后续"在宏内可表达；
   - 路由参考量=confirm 帧距角距离 − dx_opp_hit 外推（是否入角），
     外推仅作路由参考不入特征（保守）；
   - 行为测试：合成贴角/版中两态注入 → 同宏走出不同续段。
   本子项 +1 天（CE-3 总量 1.5→2.5 天）。

### CE-4 一步位置前向头（1.5 天，ppo 双实现纪律）

1. **目标**：预测下一决策点 (adx', own_corner', opp_corner', air') 4 维
   ——监督信号现成（训练 rollout 的逐拍状态序列就是真值，零采集成本）。
2. **实现**：ppo.py 加 Wf 头（trunk 表征+side → 隐层 32 → 4），
   MSE 损失，系数 λ_fwd=0.05 起步（与 aux 头同量级）；ppo_gpu.py
   同步实现，**test_gpu_onestep.py 扩展等价断言**（双实现纪律的硬
   成本，不可省）。
3. **用途**：a) 辅助损失——表征被迫编码位置动力学，压制/立回的信用
   分配提速；b) 为 CE-5 提供模型化预测器：CE-3 查表=无条件先验，
   前向头=语境修正（对手也会动），二者残差本身是信号。
4. **本轮不改动作选择**（纯辅助损失+诊断输出）。

### CE-5 反事实探测进决策（1 天，门控于 CE-3/CE-4 验收）

1. **阶段一（纯观测，默认）**：决策期对策略 top-k 宏，用 CE-3 位移表
   构造"宏后近似状态"（真实 core + 仅改距离位——尽量分布内，
   规避 value_rank 的 OOD 教训）→ V 评估 → 日志记录"策略选 A、
   反事实认为 B 优"的**分歧率**。分歧率是策略位置盲区的免费诊断
   仪表（进 F6 战报）。
2. **阶段二（干预，用户裁定项）**：logit 融合 logit_i += β·(V_i−V̄)
   仅在分歧率持续高且 B1-B4 无退化时启用；β 小步（0.1 起）。
   **红线**：阶段二未裁定不开；启用后加策略熵监控（防分布坍缩）。
3. 依赖声明：CE-4 前向头成熟后，构造状态可升级为"表先验+头修正"
   混合形态。

### CE-6 自打连段挖掘通道（1 天，依赖 CE-0.1 日志开关）

1. **复用挖掘器**：combo_mine_positional.py 适配自打日志格式（对齐
   oracle shards 最小子集：状态流+宏决策序列替代 ilog）——产出
   自打路线表（版边/空中/中央分桶，均伤/防帧口径同 R23）。
2. **半自动闭环（维持 R4/R5 验证门，不自动进库）**：
   挖掘 Top 路线 → 自动生成 hitlab 验证清单（含逐条出招脚本）→
   人工验证 → 宏库入账。"死招前科"纪律不变——闭环自动化的是
   **发现与清单**，不是**入账**。
3. **探索信号联动**：与 macro_counts（已有逐宏使用统计）交叉——
   "自打高频高伤但宏库未收录"的路线 = 探索机会清单；反之"宏库
   收录但自打从不用+低伤" = 死招候选（触发复查）。

### CE-7 推板进度势（0.5 天，奖励侧 — 2026-10-15 用户批准立项）

**问题**（2026-10-15 核验）：现势函数的角项是**二值跳变**（对手踏进
120px 圈才 +0.003，train_tm.py:336-338）——推板过程（对手从版中向角
移动的每一步）零梯度；距离势差奖励"贴近对手"而非"对手被推向角"，
方向不同。攻略的推板战术（弹幕推/绕背反关/版中打 DOWN 缩距重置）
全部无方向性回报。

1. **改动**：Φ(s) 的角项由二值改连续——
   `Φ_corner = −k_c · min(对手 x, 1280−对手 x) / 1000`（对手距近角
   距离归一，越近势越高），own 侧对称同改（我距角越远势越高）。
   势函数形态不变仍是状态函数差分 → telescoping 不可刷分性质保持
   （R35 数学保证不被破坏）。
2. **系数标定**：k_c 取值使"版中→贴角"全程势差 ≈ 现二值跳变的
   2-3 倍（放大过程信号但不压过 HP/距离主项）；回归锚：随机策略
   500 局的势差分布对比（改前/改后）入档。
3. **红线流程**：奖励方向性改动按宪法需用户批准——立项已批
   （2026-10-15），**部署排期在 A1-2 被动性 A/B 验收之后**（不污染
   观察窗口）；部署走 A/B 对照（有/无推板势各一版，观察推板战术
   出现率与对手进角频率）；F6 战报增"对手进角方式"分解（被打进/
   被推进/自己走入）。
4. 与 CE-3 的配合：位移块给"怎么推"的输入，推板势给"推有价值"
   的梯度——两者缺一只有一半。
