## 差距 #1: 决策频率（10帧 → 1-3帧）

### 目标
将有效决策频率从~10帧提升到1-3帧，使模型能在对手攻击发生帧内反应。

### 设计：三层递进

**层A: 原子宏全面化（工程，可立即实施）**

```
当前: 确认5A(6F) → 地面链(35F) → 空链(40F) → 收尾(20F)
      决策点: 4个/连段 ≈ 每25帧

原子化: 确认(6F) → 5AA(8F) → 5AAA(8F) → 5B(10F) → 236C(12F) → hjc(8F) → j5A(5F) → j2A(10F) → j2C(12F) → j66(8F) → j2A(10F)
       决策点: 11个/连段 ≈ 每10帧 → 配合R34中断=每1帧可反应
```

- 每个原子=一个宏（3-12帧），首步confirm门保留
- 原子间模型决策：读untech margin/位置/灵力/对手状态选下一原子或停
- 决策频率从宏粒度(~10帧)提升到原子粒度(~5帧)→帧级中断兜底(1帧)
- **实施**: 为三角色各拆15-20个原子宏（Trialmode帧偏移已有），追加到宏库

**层B: 帧级中断扩展（R34已起步，扩展到全条件）**

```python
# 当前R34: 对手攻击+我方硬直 → 清队
# 扩展为通用"意外检测→交还控制"框架:
interrupt_conditions = [
    ("对手攻击+我方硬直", opp_atk and my_vulnerable),      # R34已有
    ("对手防御+我方攻击中", opp_guard and my_attacking),     # 压制被防→可能被反
    ("对手untech到期", combo_chain>0 and opp_untech<=0),   # 连段对手恢复
    ("灵力临界", next_step_is_attack and spirit<100),       # R34已有
    ("位置剧变", abs(dx_prev-dx)>80),                      # 对手突进/后撤
]
```

- 不是每次都清队——每个条件有优先级和冷却
- 高优先级(对手攻击)清队；低优先级(位置变化)只设"重评估标志"
- **实施**: 在宏队列推进段加条件表，按优先级处理

**层C: 连续动作调制头（架构扩展，远期）**

```
策略网络输出:
  宏选择头: softmax over N宏（现有）
  调制头: [delay, advance, abort]  ← 新增
    delay: 0-3帧延迟（放帧/目押微调）
    advance: 提前出招（抢招）
    abort: 中止当前宏
```

- 调制头每帧输出（不只决策点）
- 与原子宏互补：原子间用宏选择头，原子内用调制头微调时序
- **实施**: ppo.py加第二输出头(3维) + train_tm帧级读取

### 依赖
- 层A无依赖（数据已有）
- 层B依赖层A（原子粒度才有意义）
- 层C依赖层A+B稳定

### 验证标准
- 层A: 对手攻击起手→我方防御的反应延迟（当前~10帧→目标<5帧）
- 层B: 连段中断率（对手恢复后我方不再白打）
- 层C: 目押成功率（当前0%→目标>80%）

## 差距 #2: 开环执行（50-90%时间盲区）

### 目标
宏播放期间从"完全盲"变为"半闭环"——能感知对手变化并做出条件分支。

### 设计：三步闭环

**Step 1: 步间确认门（立即可做）**

当前确认门只在宏首步。扩展到每一步：

```python
# 原子宏"地面链"的执行:
5AA(8F) → [confirm_5AA] → 5AAA(8F) → [confirm_5AAA] → 5B(10F) → ...
```

每个原子完成后，检查上一原子的效果：
- `d_deal > 0`（造成伤害）→ 继续下一原子
- `dec_guarded`（被防）→ 切换到压制变体或停
- 都没有（落空）→ 停（不用继续打空气）

**实施**: 原子宏间加confirm门（与首步门同机制），非原子宏在关键步后加

**Step 2: Untech驱动时序（R30特征已就位，接执行层）**

```python
# 当前: 原子间固定等待帧
((), 15)  # 等15帧

# 改为: untech条件等待
if opp_untech > my_startup:
    wait(opp_untech - my_startup)  # 等到刚好能接上
else:
    don't_continue()  # 对手已恢复，不打
```

- 模型已经有untech margin特征（R30），但执行层不用它
- 让宏帧数变成"最大等待"而非"固定等待"
- **实施**: 宏执行器加untech检查，超过固定帧数上限仍不满足则中断

**Step 3: 动态路由（原子化完成后自然获得）**

```
原子间决策时的路由表:
  if opp_untech > 10 and spirit > 500: → 选高伤原子(空链)
  if opp_untech > 5 and spirit > 200:  → 选中伤原子(地面链)
  if opp_untech <= 0:                   → 选收尾或停
  if corner and opp_airborne:           → 选版边空连原子
  if weather == 晴岚:                   → 不选SC原子(手牌不可见)
```

- 这不是硬编码路由——是让策略网络在原子间做这些选择
- untech margin/位置/灵力特征已在侧向量中，网络有全部信息
- **实施**: 无需额外代码，原子化+特征已有即可（网络自己学路由）

### 验证标准
- Step 1: 连段中断率>30%（当前被防后仍白打后续段）
- Step 2: 目押成功率>50%（当前固定帧数≈随机命中）
- Step 3: 不同条件下的原子选择分布有差异（审计可见）

## 差距 #3: 无前瞻规划

### 目标
从一步反应（"现在做什么"）到多步前瞻（"做这个之后呢？"）。

### 设计：三级规划

**Level 1: 价值引导宏选择（利用现有critic，工程量小）**

```python
# 当前: 策略网络直接输出宏（softmax over 57-69宏）
# 改为: 对每个候选宏，用critic评估后续价值，辅助选择

def select_macro(feat, side, mask, policy_probs, critic):
    candidates = top_k(policy_probs, k=5)  # 策略网络Top-5
    values = []
    for macro_id in candidates:
        # 模拟: 如果选这个宏，下一个决策点的状态会是什么？
        # 近似: 用当前状态+宏ID做critic输入
        v = critic(feat, side_with_macro(macro_id))
        values.append(v)
    # 策略概率×价值 = 选择分数
    scores = policy_probs[candidates] * values
    return candidates[argmax(scores)]
```

- 不改变训练（仍然PPO），只改推理时的宏选择
- 利用现有critic网络，零新参数
- 相当于一步前瞻搜索（depth=1）
- **实施**: train_tm的sample()调用处加critic辅助选择

**Level 2: 对手反应预测（利用现有aux预测头）**

```python
# aux预测头(R17④)已预测对手下一拍动作类
# 扩展: 预测"如果我做X，对手会做什么"

def plan_with_opponent_model(feat, side, policy, aux_head):
    my_options = top_k(policy(feat, side), k=3)
    for opt in my_options:
        opp_pred = aux_head(feat, side, my_action=opt)  # 对手会怎么应对
        my_followup = policy(feat_after(opt, opp_pred), side)  # 我怎么接
        value = critic(feat_after(opt, opp_pred, my_followup))
        # 两步前瞻: 我做X→对手做Y→我做Z→价值V
```

- aux预测头已存在（R17④），当前只做表征学习，不做决策
- 扩展为两步前瞻: 我→对手→我
- **实施**: ppo.py加规划推理方法（训练不变，推理时用）

**Level 3: 策略条件化（架构演进）**

```
高层策略: "当前应打进攻/防守/中立/压制？"
  ↓ 条件化
低层执行: 从对应策略的宏子集中选择

实现: 策略网络加"模式头"(4维: 进攻/防守/中立/压制)
  - 模式头输出作为侧向量额外特征
  - 宏掩码根据模式收紧(进攻模式禁防御宏, 防守模式禁攻击宏)
  - 模式由策略网络自身学习(端到端)
```

- 类似AlphaStar的"宏观策略→微观执行"分层
- **实施**: ppo.py加模式输出头 + 掩码联动

### 验证标准
- Level 1: 宏选择质量提升（同样状态下选的宏伤害期望更高）
- Level 2: 对"对手大概率防御"的情况选择投技/延迟攻击
- Level 3: 不同模式下宏分布有显著差异

## 差距 #4: 样本效率

### 目标
减少达到同样水平所需的对局数（当前~500局/批）。

### 设计：三路提效

**路径A: 离线RL从神谕数据（数据已有，需新训练管道）**

```
当前: 神谕191局只用于BC锚（模仿"做什么"）
改进: 同时用于离线RL（学习"什么奖励"）

方法: Conservative Q-Learning (CQL) 或 IQL
  - 从神谕数据学Q函数（"在这个状态下做这个动作值多少"）
  - Q函数作为额外critic信号辅助PPO
  - 不改变在线训练流程，只是加一个预训练步骤
```

- 神谕数据含完整(状态, 输入, 下一状态, 伤害)元组
- 可学出"专家在此获得的奖励"作为return基线
- **实施**: 新工具从oracle_v2提取(state,action,reward,next_state)元组 → CQL预训练critic → PPO加载

**路径B: 经验回放池（PPO改进）**

```
当前: PPO 1 epoch后丢弃数据
改进: 保留高优势样本, 跨批重用

方法: 优先经验回放(PER)的on-policy变体
  - 每批结束后, 保留|advantage|>1σ的样本
  - 下一批以20%比例混入
  - 用importance ratio修正off-policy偏差
```

- 不改变算法本质(PPO→ε-PPO)，只是重用好经验
- 预期减少30-50%所需对局数
- **实施**: ppo.py的update()加经验保留+混入

**路径C: 世界模型想象训练（远期）**

```
学习游戏动态: s' = f(s, a)
在想象中训练: 不需要真实对局, 在世界模型中rollout
```

- 需要学习精确的62fps游戏动态（含弹幕/天气/hitstop）
- 复杂度高但一旦建成, 样本效率提升100倍+
- **实施**: 远期，需先完成原子化+特征稳定

### 验证标准
- 路径A: 同样对局数下胜率提升（+10%以上）
- 路径B: 达到同样水平所需对局数减半
- 路径C: 想象rollout与真实对局的状态误差<5%

## 差距 #5: 奖励代理化

### 目标
减少手工奖励被钻空子的风险，渐进走向真实目标（胜负）。

### 设计：奖励进化三阶段

**阶段1: 势函数塑形（立即，数学保证不改变最优策略）**

```
当前: r = Σ(手工通道) — 可能改变最优策略
改为: r = Φ(s') - Φ(s) + r_true
  Φ(s) = 势函数（只依赖状态，不依赖动作）
  r_true = 胜负奖励（KO=+10, 被KO=-10）

势函数示例:
  Φ(s) = 0.001×(对手HP下降) + 0.0005×(我方灵力) + ...
         - 0.001×(我方HP下降) - ...
```

- **关键性质**: 势函数塑形不改变最优策略（Ng et al. 1999证明）
- 当前手工奖励大部分可转化为势函数形式
- 被钻空子的通道（graze/防御/立防）天然消失——势函数不奖励"待在某状态"
- **实施**: train_tm的奖励计算改为potential-based形式

**阶段2: 奖励通道渐进裁剪（中期）**

```
当前: ~12个通道（伤害/承伤/防御/擦弹/规避/墙/灵力/KO/空挥/位置/角/连段偏置）
目标: 3-4个通道（胜负/伤害差/资源差/位置势）

裁剪路径: 每当某通道连续5轮诊断无显著行为影响→标记为"可裁剪"
  → 裁剪后观察一轮→无退化→确认裁剪
```

- 势函数化后许多通道变得冗余（势函数已隐含）
- 减少通道数=减少被钻空子的表面积
- **实施**: 诊断→标记→裁剪循环

**阶段3: 纯胜负+BC（远期）**

```
r = win ? +10 : lose ? -10 : 0
+ BC anchor（神谕行为克隆防随机漂移）
```

- 只有当模型已足够强（不会因稀疏奖励而退化）时才可行
- AlphaGo/AlphaStar最终都用纯胜负
- **实施**: 当对COM胜率>50%时切换

### 验证标准
- 阶段1: 势函数化后最优策略不变（理论上保证，实证:胜率不降）
- 阶段2: 每裁剪一个通道, 胜率无显著下降
- 阶段3: 纯胜负下模型持续进步

## 差距 #6: 连段弹性

### 目标
从固定脚本到实时条件分支——版边/灵力/天气/对手选择都影响路线。

### 设计：条件原子+路由

**组件A: 位置条件原子（原子化的自然扩展）**

```
# 每个原子标注其适用条件:
atoms = {
    "地面链A": {condition: dx_mid, corner: False, air: False},
    "版边链A": {condition: corner=True},      # 版边专用(伤害更高)
    "空链A":   {condition: opp_air=True},     # 对手浮空时
    "低灵链":  {condition: spirit<300},       # 灵力不足时的简化版
    "天气链":  {condition: weather=晴岚},      # 晴岚时不用SC
}
```

- 掩码系统已有（R23位置门控/R24射程门控），只需扩展到原子级
- 每个原子标注条件 → 决策时掩码自动过滤不适用原子
- **实施**: 原子宏定义加条件标注 + 掩码构建扩展

**组件B: 灵力感知路由**

```
# 在原子间决策时, 策略网络看到灵力特征(已有)
# 但我们可以在掩码层做硬门控:
if spirit < 200:
    mask off: 所有含B/C键的原子（弹幕需要灵力）
if spirit < 100:
    mask off: 所有含A键的连段后续（连段收尾需要灵力）
```

- R34灵力门控是"执行中检查"，这是"决策时预防"
- 双保险：决策时掩码+执行中门控
- **实施**: 掩码构建加灵力条件

**组件C: 对手选择适应**

```
# 连段中对手可能选择: 受身/无受身/空中受身/延迟受身
# 当前: 固定连段不管对手怎么选

# 改进: 原子间决策时读对手untech和action:
if opp_untech == 0 and opp_action in (180,181,197,198,199):
    # 对手已受身 → 追击原子(空中连)
    route_to("空链A")
elif opp_untech == 0 and opp_action == 0:
    # 对手无受身倒地 → 起身压制原子
    route_to("压制B")
else:
    # 对手仍在hitstun → 继续连段
    route_to(policy_choice)
```

- 这不是硬编码——是给策略网络更多"情境→路线"的原子选项
- 策略网络通过PPO学习哪种情境选哪种路线
- **实施**: 添加受身追击原子+起身压制原子

### 验证标准
- 组件A: 版边/中央的原子选择分布显著不同
- 组件B: 空灵力时不再选弹幕原子
- 组件C: 对手受身后不再白打原连段路线

## 实施优先级与依赖图

```
差距#1 层A(原子全面化) ──────────────┐
    ↓                                │
差距#2 Step1(步间确认) ──→ Step2(untech时序) ──→ Step3(动态路由) ←─ 差距#6
    ↓                                ↑                    ↑
差距#1 层B(中断扩展) ────────────────┘                    │
    ↓                                                      │
差距#3 Level1(价值引导) ──→ Level2(对手预测) ──→ Level3(策略条件化)
                                     ↑                      ↑
差距#4 路径A(离线RL) ──→ 路径B(经验回放) ──→ 路径C(世界模型)
    ↑
差距#5 阶段1(势函数) ──→ 阶段2(裁剪) ──→ 阶段3(纯胜负)
```

**推荐实施顺序**:
1. 差距#5 阶段1（势函数化）— 数学保证，零风险，消除刷分根源
2. 差距#1 层A（原子全面化）— 已有试点，扩展到三角色
3. 差距#2 Step1+2（步间确认+untech时序）— 依赖#1层A
4. 差距#3 Level1（价值引导）— 利用现有critic，改动小
5. 差距#6（条件原子+路由）— 依赖#1+#2
6. 差距#4 路径A+B（离线RL+回放）— 独立可做
