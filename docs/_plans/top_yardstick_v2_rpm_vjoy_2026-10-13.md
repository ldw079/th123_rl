## 1. 方案主体——四件套（纯工具路线, 零 mod 改动）

### B-1 · 观察通道: RPM 轮询状态读取器（1.5 人日）

**新增 `tools/rpm_observer.py`**:
```
RPMObserver(exe_hash_guard=True)
  .start(pid) → 绑定进程+校验 exe 哈希（th123.exe 版本变更即响亮拒连）
  .read_frame() → dict（与 105B CS_FIELDS 同构的 left/right/weather/objs）
```

- **偏移链核验优先（0.5 人日）**: 已确认的 scene/HP/score/位置/动作/朝向（问题书 §2.3）直接复用 tm_env 的地址表; **待核验**: 灵力(+0x1A8?)/手牌/天气/对象列表（弹幕）——用 rl_game 被动观测 mod 的 sendState 输出做**真值对照**（一次校准会话: mod 流式 RPM 双路并行, 逐帧 diff 定全部偏移, 誤差=0 即核毕）;
- **帧同步**: 游戏渲染 ~60fps → 轮询同频 60Hz; 逻辑帧号读 `frameCount`（CharacterManager 内已有偏移）; 帧号不增=渲染间隙/加载, 跳过;
- **公平垫片（C'）**: `read_frame()` 内置 **5 帧环形缓冲**——每读一帧入队, 返回 t-5 帧的快照（纯观察延迟, 行动不经延迟——简化版垫片; W1 全管线版上线后升级）;
- **R11 信息遮蔽**: 读到的真值在 observer 侧执行与训练观测同构的遮蔽（极光天气→displayed、晴岚手牌→0xFF）——规则复制自 feat_builder.fair_weather_id / gauge_feat, **不直读被遮蔽量**;
- **CPU 成本**: 60Hz × ~20 次 RPM 读 = ~1200 次/秒, 实测 tm_env._watch 同频无感。

**验收**: 与 mod 流式输出校准: 连续 3 局逐帧 diff=零（位置/HP/灵力/手牌/弹幕数）; exe 哈希变更→拒连; 5 帧缓冲行为断言。
**门禁**: 偏移表行为断言（合成内存→字段值, 含遮蔽规则）+ exe 哈希变异; 帧号单调性断言。

### B-2 · 行动通道: vJoy 虚拟手柄驱动（1 人日）

**安装（0.5 人日含配置）**:
- vJoy **安装到 D 盘**（用户已裁定）; `pip install pyvjoy`（或 ctypes 直调 vJoyInterface.dll——优先后者, 免新依赖）;
- **兼容性探针（半天, 一次性）**: 原版整合包（ControlPnP+DPadFix+giuroll 全开）下 vJoy 虚拟手柄 → P2 键位设置中可见且可绑定; **若不可见**: 回退排除法（逐禁用 ControlPnP/DPadFix/giuroll 直到可见, 找冲突 mod; 若全部禁用仍不可见 → [用户裁定项 B-2a] 是否接受临时禁用某 mod 或切换 ViGEm）;

**新增 `tools/vjoy_driver.py`**:
- 键位映射: 协议输入位（H/V/A/B/C/D/SC/SW）→ vJoy 轴/按钮（H=axis X, V=axis Y, A/B/C/D=button 1-4, SC=button 5, SW=button 6）; 用户游戏内绑定 P2 手柄到 vJoy 虚拟设备;
- **帧节拍器**: 60Hz 写入（与游戏渲染同步; py 侧 time.sleep(1/60) 循环+漂移校正）;
- **公平**: 行动不经延迟垫片（模型决策→vJoy 即时, 延迟只在观察侧）——人类"看到→反应→按"也只延迟观察侧, 语义对齐。

**验收**: vJoy 写入→游戏内 P2 响应（人工确认一招一出）; 60Hz 节拍稳定（漂移 <5ms/帧）; 键位映射行为断言。
**门禁**: 映射表行为断言 + 节拍器频率断言。

### B-3 · 对局组织: 人测会话 runner（1 人日, 复用既有资产）

**新增 `tools/human_match_v2.py`**（旧 human_match.py 的 poll 模式退役归档）:
- **会话生命周期**: 用户手动启动原版游戏（无端口参数, 日常 mod 集在用）→ runner attach（RPM 绑定+vJoy 启动）→ 用户游戏内选 VS PLAYER/P2=vJoy 手柄 → 对局开始;
- **模型侧**: RPMObserver 60Hz 读帧 → 5 帧缓冲 → FeatureBuilder.build → SideDriver.sample → vjoy_driver 写入——**完整在线推理链, 与训练同构**;
- **系列赛**: 接 SeriesManager(series_len, series_win)——BO5/BO15 参数化; 系列内对手画像不重置（与训练侧同构, 问题书 §2.3 已在）;
- **锚定段**: 会话开头用户先打 3 局 COM Lunatic（无模型介入, runner 仅 RPM 记录→统计 COM 胜率, 与模型周报的 COM 胜率投影到同尺）;
- **rep 归档**: 游戏内 SaveRep mod 自动存 rep（已在役）→ runner 监视 replay 目录（复用 human_solo_collect 的目录监视逻辑）→ 归档+模型快照版本+exe 哈希三方绑定;
- **会话报告**: 同 B-3 草案格式（锚定/主测/逐场/习惯/rep 路径/raw_keys 不再需要——键盘输入不经我们）;
- **fleet 降容**: 会话启动时向 fleet_supervisor 发降容信号（`tools/fleet_pause.py` 新增: 暂停/恢复, 走既有看门狗的 manual switch）; 会话结束恢复。

**验收**: 一次完整三段会话（锚定 3 局+BO5+归档）; 模型在 BO5 中有真实决策（非全待机/全崩溃）; 用户体感无输入延迟/无帧率下降。
**门禁**: 会话 json 格式断言; SeriesManager 接入断言; fleet 暂停/恢复行为断言。

### B-4 · F6 评估矩阵接入（0.5 人日）
