# 现有模型架构 vs 超人目标：全面差距分析

> 2026-10-02 · R33 后 · 基于对全部源码的逐层审视

## 0. 超人模型的定义

格斗游戏的"超人"指：
- **反应速度**：识破对手起手并在发生帧内应对（人类 ~15 帧，超人 <5 帧）
- **执行精度**：所有目押/放帧 100% 成功，连段路线实时最优
- **战略深度**：多步前瞻（"我逼他防→他大概率抢招→我放帧抓"），非一步反应
- **适应速度**：2-3 次交手即可识别对手习惯并调整对策（人类顶尖需一整局）
- **资源管理**：灵力/卡牌/天气利用全局最优

## 1. 感知层

### 已有（优于人类的部分）

| 能力 | 现状 | 人类对比 |
|---|---|---|
| 状态信息 | 完全可见（mod 提供全部物理量） | 需肉眼读屏幕 |
| 精确坐标 | 双方 x/y 精确到浮点 | 估读像素 |
| 弹幕追踪 | 逐帧最近邻匹配 + 加速度/转向/引信 | 肉眼只看弹幕群 |
| 攻击范围 | XML hitbox 权威射程表 | 经验记忆 |
| 发生帧 | 枚举级精确 startup 表 | 经验估计 |
| untech 时序 | 对手 untech 帧数实时可读 | 计数直觉 |

### 差距

| 缺失 | 影响 | 严重度 |
|---|---|---|
| **动画帧级识别** | 看不到"5A 第 3 帧 vs 第 5 帧"（60×80 低分辨率网格只能区分有/无攻击，不能区分攻击进度）—— 无法做发生帧内反应 | ★★★★★ |
| **hitbox/hurtbox 可视化** | 空间判定只靠 reach 标量 + 位置差值，不知道"蹲姿 hurtbox 变矮"这类帧级碰撞变化 | ★★★★ |
| **弹型行为先验** | 追踪弹的加速度/转向是"观测后推断"，不知道"萃香 2C 引信 50 帧半径 R"（需弹型画像表） | ★★★ |
| **天气效果量化** | 天气 ID 是标量，不知道"当前天气下 hitstun +20%"这类机制修正 | ★★★ |
| **对手卡组/装备推理** | 看不到对手手牌构成（mod 只给当前手牌数），不能推断"他可能装了 236C 升级" | ★★ |

**结论**：感知层信息获取已超人（精确坐标/速度/资源），但**信息加工不足**——特别是动画帧级进度和碰撞盒几何。

## 2. 决策架构

### 已有

| 能力 | 现状 |
|---|---|
| 动作空间 | 宏库（57-66 个选项，含连段/压制/防御/SC） |
| 决策频率 | ~10 帧/次（宏队列空时） |
| 策略网络 | PPO + 共享 conv 主干 + 5 块侧向量 |
| 掩码 | 距离/位置/射程/符卡/背向 5 层门控 |
| 对手模型 | 75 维（情境×行为×历史×资源条件化） |
| BC 锚 | 神谕数据 + Trialmode 连段 |

### 差距（这是最大的瓶颈层）

| 缺失 | 现状 | 超人需要 | 差距量化 |
|---|---|---|---|
| **决策频率** | ~10 帧（160ms） | 1-3 帧（16-48ms） | **3-10 倍差距**。10 帧粒度下：对手 5A 发生 6 帧 → 模型来不及切防。这是**无法通过更好策略弥补的硬天花板**。 |
| **宏内开环执行** | 宏播放期间（20-100 帧）不感知对手变化（除 hitstop/受击中断） | 每帧感知 + 条件分支 | **~50-90% 的实际游戏时间处于盲区**。超人玩家在连段中每帧都在读对手 DI/受身选择。 |
| **多步前瞻** | 价值函数一步估计（γ=0.999 但无显式规划） | "我逼防→他抢→我放帧抓"3-5 步推理 | 无树搜索/规划模块。AlphaGo/AlphaStar 均需搜索。 |
| **实时择（mix-up）** | 一次决策一个宏，不能"如果他防→投，如果他动→打" | 情境→分支→再分支 | 确认门是原始形态（命中/落空二分），远不够 |
| **并行攻防** | 单一策略网络同时管攻防 | 攻击规划器 + 防御反应器独立运行 | 10 帧粒度下"边压制边准备防"不可能 |
| **对手特定策略** | 对手模型是观测（"他在做什么"）非决策（"我该怎么打他"） | "他是冲刺型→我用弹幕拦截"风格对策 | 75 维特征进策略但无显式策略条件化 |

**结论**：决策层是**与超人差距最大的层**。核心瓶颈是宏抽象——它把动作空间从连续压缩到 ~60 选项（好的初始设计），但也把决策频率锁死在宏粒度、把执行锁死在开环。

## 3. 学习架构

### 已有

| 能力 | 现状 |
|---|---|
| 算法 | PPO（1 epoch, MINIBATCH=64, KL 自适应 LR） |
| 数据源 | 自对弈（3 角色 × k=3 快照池）+ 神谕 BC |
| 奖励 | 手工混合（伤害/防御/擦弹/位置/KO/空挥…约 12 通道） |
| 探索 | 温度退火 + 新宏配额 + 连段偏置 |

### 差距

| 缺失 | 影响 | 超人系统怎么做的 |
|---|---|---|
| **样本效率** | PPO 同策略 1 epoch 需海量交互。当前 ~1000 决策/局 × 500 局/批 = 50 万决策达到当前水平 | AlphaStar 用了数千万局。OpenAI Five 用了 128 GPU × 数月 |
| **真正的目标优化** | 手工奖励是代理——反复被刷分（立防/graze/防御三轮），每修一个出下一个 | 超人系统最终只优化胜负（reward = win/loss），中间用课程 |
| **课程学习** | 从随机策略直接打全角色 | 应从"固定对手简单策略"→"池对手"→"自我对弈"→"联盟"渐进 |
| **联盟/利用者** | 3 角色固定池，无 exploiter（专门克制当前弱点的对手） | AlphaStar 的联盟训练是达到超人的关键 |
| **模型基础 RL** | 无世界模型（无法想象"如果我做 X，30 帧后会怎样"） | MuZero 类系统用学习到的动态模型做规划 |
| **离线大数据利用** | 神谕 191 局只用于 BC 锚（模仿），未用于离线 RL（学习"专家在此做了什么+什么奖励"） | AlphaStar 用人类数据做行为克隆+奖励推断 |

**结论**：学习层的 PPO+BC 能达到"强业余"，但到超人需要根本性架构变化——联盟训练、搜索、模型基础 RL。

## 4. 执行层

### 已有

| 能力 | 现状 |
|---|---|
| 宏脚本 | 含精确帧数（CHM 攻略 + Trialmode 帧偏移） |
| 确认门 | confirm（命中才放）/ cconfirm（命中或被防都放） |
| 等级条件化 | 技能升级后取消帧减 |
| 方向预置 | 6 帧预置防吞键 |
| hitstop 保键 | 冻结期间不倒计时 |
| untech 差值特征 | clip((opp_untech - startup_i)/50) |

### 差距

| 缺失 | 影响 | 超人执行 |
|---|---|---|
| **动态时序** | 帧数写死。hitstun 受伤害缩放/天气/角色体重影响——固定帧数在非标定条件下脱轨 | 每帧读对手 untech/状态，实时微调出招时机 |
| **连段路由** | 预编脚本的路线固定（民工连A/B/C）。版边/灵力/天气变化应换路线 | 实时条件→路线选择（"灵力不够→跳过 B 直接 C"） |
| **option select** | 不能一个输入覆盖多种对手反应（如"防+投"同时判定） | 高手大量使用 OS 提高容错 |
| **目押精度** | 帧数在宏内固定，且决策粒度 10 帧意味着原子间的衔接只能靠等待帧 | 1 帧精度、实时条件分支 |

**结论**：执行层的精确数据已有（Trialmode 帧偏移），但**弹性为零**——任何偏离标定条件的情况都会导致脱链。

## 5. 差距排名（按达到超人的阻碍程度）

| 排名 | 差距 | 为什么最阻碍 | 现有架构能否渐进解决 |
|---|---|---|---|
| **1** | 决策频率（10 帧 → 1-3 帧） | 即使策略完美，反应速度不够就永远慢一拍。这不是精度问题，是**物理上限** | ❌ 宏抽象内无法解决。需要原子化+帧级中断 |
| **2** | 开环执行（50-90% 时间盲区） | 连段中不能适应对手选择（DI/受身/防御切换），压制中不能对抢招做反应 | ⚠️ 部分可解（原子化+untech 条件分支），但需要决策频率提升配合 |
| **3** | 无前瞻规划 | 立回（neutral game）是 3-5 步博弈。一步反应型策略上限是"强反应型"而非"战略性超人" | ⚠️ 可在宏抽象上做（"选哪个宏"隐含规划），但上限有限 |
| **4** | 样本效率 | PPO 需要的数据量与可用训练时间不匹配 | ⚠️ 可通过离线 RL + 联盟缓解，但需架构变更 |
| **5** | 奖励代理化 | 手工奖励反复被钻（已修三轮：空防/graze/立防），每修一个出一个 | ✅ 可通过渐进简化奖励+增加真实胜负权重解决 |
| **6** | 连段弹性 | 影响伤害上限和条件适应 | ✅ 原子化+动态路由可解 |

## 6. 现有架构的真实水平定位

| 维度 | 当前水平 | 超人水平 | 差距 |
|---|---|---|---|
| 信息获取 | **超人**（精确坐标/速度/资源/弹幕） | 同 | 0 |
| 信息加工 | 业余（帧级动画不可辨） | 超人 | 大 |
| 反应速度 | **低于人类**（10 帧粒度 ≈ 160ms vs 人类 ~250ms 但人类可预读） | 超人（<50ms） | 极大 |
| 执行精度 | **业余偏上**（宏内帧数精确但无条件分支） | 超人（100% 自适应） | 大 |
| 战略深度 | **入门**（一步反应+简单对手建模） | 超人（多步前瞻+对手特定策略） | 极大 |
| 适应速度 | **入门**（对手模型 ~30 秒积累） | 超人（2-3 次交手） | 大 |
| 资源管理 | **入门**（灵力感知奖励，无全局规划） | 超人 | 大 |

**一句话定位**：当前架构是"信息超人 + 决策婴儿"——看得比任何人都清楚，但反应比新手还慢，且不能想多于一步。

## 7. 渐进路径（不推翻重来）

### 阶段 1：消除硬天花板（当前 → 能反应）

**目标**：决策频率从 10 帧 → 3 帧
- **连段原子化**（已有设计）：每原子 3-5 帧，原子间决策
- **帧级中断系统**：宏播放期间每帧检查对手状态变化，满足条件即中断交还决策权
- **untech 驱动时序**：不再用固定帧数，每帧读 opp_untech 决定"现在出还是再等"
- 这不需要改感知层和奖励层，只需要改执行层

### 阶段 2：消除盲区（能反应 → 能适应）

**目标**：开环 → 半闭环
- **动态连段路由**：原子间决策时看位置/灵力/天气选下一原子
- **实时择**：确认门从二分（命中/落空）扩到多分支（命中/被防/被闪/被反）
- **防御反应器**：并行进程监测对手攻击起手，自动触发防御宏（不经策略网络，反射弧）

### 阶段 3：获得战略（能适应 → 能规划）

**目标**：一步反应 → 多步前瞻
- **价值函数做规划**：用当前 critic 评估"选宏 A 后 30 帧的价值 vs 选宏 B"
- **对手风格条件化**：对手模型特征显式进策略（"对冲刺型对手→弹幕拦截优先"）
- **联盟训练**：加入利用者对手（专门克制当前弱点）

### 阶段 4：超人（远期）

- 连续动作空间（去除宏抽象，直接输出按键帧序列）
- MCTS + 学习到的动态模型
- 真实胜负奖励（去除全部手工 shaping）
- 跨角色泛化（一个模型打所有角色）

## 8. 今天到阶段 1 的具体差距

| 需要 | 已有 | 差 | 怎么补 |
|---|---|---|---|
| 原子宏（3-5 帧粒度） | 设计完成（Trialmode 四段拆分） | 未实施到宏库 | 追加原子宏+BC repad |
| 帧级中断 | hitstop/受击中断（粗粒度） | 无"对手起手→我中断"路径 | 加帧级对手状态检查 |
| untech 驱动时序 | untech 差值特征（R30 已上线） | 特征有了但宏帧数还是固定的 | 原子宏间等待条件化 |
| 防御反射弧 | 确认门（宏内）+ 掩码（决策级） | 无帧级自动防御 | 独立监测线程+反射宏 |

**总结**：从当前到"能反应"（阶段 1）的距离是**工程实施**（设计已完成），不是架构突破。从"能反应"到"超人"（阶段 2-4）的距离是**架构演进**（需逐步去除宏抽象、加入搜索/联盟/世界模型）。
