# F6 超人距离度量 — 现在算什么、为什么还不是"距离"（R63, 2026-10-07）

> 起因: 用户要求"把负责测算超人距离的代码块完善到可用"。
> 结论先行: **度量已可用且全部可证伪；但"到超人的距离"这个数给不出来 —
> 因为项目缺少与模型评估同口径的人类基线。** 本文件说明缺口在哪、需要什么。

## 1. 原来那段代码（占位口径）

`tools/eval_matrix.py` 只有一行:

```python
metric = top['avg_wr'] - top['var']      # 胜率均值 − 胜率方差
```

三个问题（审查实证）:

| 问题 | 说明 |
|---|---|
| 量纲无意义 | 用一个"胜率"去减一个"胜率的方差", 没有统计含义, 也无上下界 |
| 不是距离 | 不含任何基准(人类/COM/满分) → 没有"离目标多远"的参照点 |
| 小样本不自知 | 盘上 `eval_matrix_quick_20261007.json`: marisa 每对**只打2局**全胜 → `metric = 1.0`(满分)。1W-0L 与 50W-0L 同分 |

项目文档此前也如实记为"占位口径/占位读数"— 本次把它换掉。

## 2. 现在给的是三件可证伪的东西

代码: `tools/superhuman_gauge.py`（离线、无 torch、无游戏）

### 2.1 `dominance` — 最差对位下界

- 取每个角色**最薄弱对位的 Wilson 95% 下界**，再取全体最小值。
- 为什么不用"平均胜率": 平均值会把弱对位平均掉。超人的定义特征是
  **没有弱对位**，所以取最差那个的保守下界。
- 自测用例证明它有效: a 对 b/c/d 全胜 3-0、被 e 打 0-4 → 平均胜率仍有
  **0.692**（"平均值会骗人"），而下界是 **0.000**（弱对位被锁定）。
- `min_games` 门: 低于阈值的对位**不参与判定**但被如实列出（不当 0、不隐藏）。
- `reliable` 标注: 样本偏小时明确写 ⚠（每对2局时一次失利即可压到0）。

### 2.2 `human_anchor` — 真实人类基线（本项目唯一真人数据，此前从未接线）

数据源: `data/oracle/shards/*.npz` = **真人 vs 真人 网络对战重放**，
191 局可用（meta 含 char_x/char_y 与 `score_final` 回合比分）。

| 角色 | 真人胜率 | Wilson 95% | 局数 |
|---|---|---|---|
| marisa | 67.2% | [0.544, 0.779] | 58 |
| reimu | 51.2% | [0.436, 0.588] | 162 |
| suika | 42.6% | [0.352, 0.503] | 162 |

派生档 `data/human_baseline.json`(2.2KB) 供快速/沙箱读取；
重放原文是唯一真值源，`--rebuild` 可随时重建。

### 2.3 `comparison` — 只在同口径时给"距离"

当前 **`comparable=False`**，`distance=None`，并给出原因（不是缺省值）：

> 人类数据是"真人 vs 真人"（对手=另一个真人），模型矩阵是"模型 vs 模型快照"
> （对手=同架构策略）— **对手分布不同，胜率之差不是能力之差**。

## 3. 为什么"距离"这个数现在给不出来（诚实的缺口）

最干净的超人判据看起来是:

```
超人距离 = 模型对COM胜率 − 人类对COM胜率        （同一批固定对手）
```

**但这条公式是错的，本文件先前版本也误判了缺口所在。** 用户 2026-10-07 给出
实测口径:

> **真人对 COM 的胜率是百分之百，COM 的水平远逊于真人。**

这直接决定: **COM 在天花板处饱和，不可分辨**。

| | 真人 | 超人 |
|---|---|---|
| 打 COM | 100% | 100% |

两者读数相同 → 对 COM 的胜率只能回答"**模型是否已低于人类下限**"，
**永远无法**回答"比人类强多少"。所以缺的**不是**"真人 vs COM 数据"
（那份数据即使补上也没用），而是一个**能区分顶端的标尺**。

正确判据（二选一）:

1. **真人 vs 该模型直接对打** —— 最强的证据，但需要人上机；
2. **在同一批固定对手上同时测真人与模型** —— 且该对手必须是人类也会输的
   （否则同样饱和），例如顶级人类互相之间、或人类 vs 当前模型快照。

代码据此调整:

- `COM_VS_HUMAN` 常量记录该事实（含来源），`com_ruler_verdict()` 给出
  "该标尺此刻能说什么/不能说什么"的四档判定：
  `below_human_floor`（对COM输=确定低于人类下限）/
  `indistinguishable_from_human`（区间跨100%，样本小或标尺饱和）/
  `at_or_above_human_on_saturated_ruler`（大样本全胜，仍**拒绝**称超人）/
  `no_data`。
- `comparison.comparable` 只在"标尺可分辨"时为 True；检测到真人vs COM 数据时
  会明确写出"该标尺饱和，不可作分母"。

**没有做的事**: 拿"人-人胜率"去减"模型-模型胜率"，或用"模型打COM=100%"宣称超人。
两者都是看起来很专业、实际无意义的数字 —— 正是上一版占位口径的错误。

## 4. 另一条必须在文档里说清的限定

`eval_matrix` 的对手是**同架构策略快照**（`SideDriver` 加载 `model_ppo_X.npz`）。
因此:

- 它的对位胜率度量的是**对抗池广度/对手强度**，**不能**读作角色或策略的绝对强弱;
- 镜像对位（如 reimu vs reimu）≈50% 是**算法对称性的必然结果**，不是"平衡性结论";
- 旧报告里的"角色强度排名"据此不成立（已在新输出里改称"按平均对位胜率"并加注）。

要得到角色/策略的绝对强弱，需要**外部标尺**（COM 各难度 / 固定的人类基线 / 真实对手）。

:: 重建人类基线派生档(从重放原文)

视角，胜/负互补）；单侧口径用于"只有一侧是模型"的评估。

## 7. 若要真正给出"超人距离"，需要什么

**已确认不需要的**: 真人 vs COM 数据 —— 用户实测真人打 COM 恒 100%，
该标尺在天花板处饱和（人类与超人在此读数相同），补上也不能当分母。
本文件早先版本把缺口判成"缺这份数据"，是错的，此处更正。

| 需要 | 现状 | 谁来做 |
|---|---|---|
| **能区分顶端的标尺**（关键） | 缺 | 见下两行 |
| 真人 vs 该模型 直接对打 | 0 局 | 真人上机（最强证据） |
| 或: 同一批固定对手（人类也会输的那种）上同时测真人+模型 | 需设计对局协议 | 真人上机 |
| 模型 vs COM（各难度） | 工具已有 `outer_loop.py comeval` | 脚本 |
| 每对位足够局数(`--games ≥ 8`) | 当前矩阵每对 2 局 | 脚本(耗时) |

前三行（能区分顶端的标尺）齐备后，`comparison` 会自动从"不可相减"转为
给出差值并附两侧 Wilson 区间 —— 那时它才配叫"超人距离"。

## 8. COM 标尺此刻仍有的用处（低成本守门）

虽不能量距离，它能给出**确定性的下限判定**，可日常跑:

```bat
:: 给定"模型 vs COM"读数, 看该标尺能说什么/不能说什么
D:\temp\pyenv\python.exe -X utf8 tools\superhuman_gauge.py --com-wr 0.8 --com-games 10
```

| 模型 vs COM | 判定 | 含义 |
|---|---|---|
| 输/非全胜 | `below_human_floor` | **确定低于人类下限**（区间上限<100%） |
| 全胜但局数少 | `indistinguishable_from_human` | 与人类不可区分，**不能**称超人 |
| 大样本全胜 | `at_or_above_human_on_saturated_ruler` | 未观测到低于人类，**仍拒绝**称超人 |

配合 `outer_loop.py comeval` 可作"毕业制"的守门指标: 只要还没到
"大样本全胜", 就明确还没到人类下限之上。
